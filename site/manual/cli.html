#Common options

NyrexVJ can be started with options. Most are for tests and screenshots, a few are useful in daily work.

OptionEffect
--preset NAMELoad a factory or user preset on start
--freshIgnore the saved session
--lang CODEStart in this language: en, de, es, fr, it, pt, nl, ja or the code of a language file
--outputOpen the output windows on start
--venue NAMELoad a saved venue setup on start
--ndi NAMEStart the NDI sender with this name
--osc-port NListen for OSC on port N even if it is switched off in the settings
--audio-demoUse the demo audio signal
--no-update-checkSkip the update check
--no-pluginsSwitch plugins off for this run
--welcome and --no-welcomeForce or skip the welcome screen
--manualOpen this manual on start, optionally at a chapter, for example --manual outputs
--timelineOpen the show timeline window on start
--show-packagesOpen the Show package window on start, on the Export tab, or on the Import tab with --show-packages 1
--community-packagesOpen the Community packages window on start, on the Installed tab, or on the Install tab with --community-packages 1 or the Create tab with 2
--pack-build FOLDER FILEBuild a community package from a folder and exit, with --pack-overwrite to replace an existing file
--pack-info FILEShow what a community package holds and whether it could be installed, and exit
--pack-install FILEInstall a community package and exit, with --pack-accept-plugin, --pack-allow-downgrade, --pack-keep-mine or --pack-replace where they are needed
--pack-remove IDRemove an installed community package and exit
--generatorsOpen the Text and particles window on start, on the Text tab, or on the Particles tab with --generators 1
--chainsOpen the Effect chains window on start for layer 1, or for layer 2 to 4 with --chains 1 to --chains 3 and the master with --chains 4; --chain-select NAME selects a chain
--generator-selftestCheck text and particle clips in the real engine and exit, with a number of frames after it for a benchmark and --bench-out FILE.json for the result
--settings IDXOpen Settings on page IDX, counted from 0 in the order of the page list
--check-shadersCompile every shader and exit
--shader-editor [FILE]Open the shader editor on start, with a file of the shaders folder if you give one, otherwise with a template
--shader-editor-selftest [FRAMES]Check the shader editor in the real engine and exit, with a number of frames after it for a benchmark and --bench-out FILE.json for the result
--shader-editor-uitestDrive the shader editor with real key and mouse events, check what it holds and exit with code 0 or 1, with --bench-out FILE.json for the result
--routing-selftest [FRAMES]Check video routing in the real engine and exit, with a number of frames after it for a benchmark and --bench-out FILE.json for the result
--routing-demoBuild a small example with route clips and open the Video routing window, for screenshots
--netsync-selftestCheck the network sync in the real engine in both roles with a lossy relay and exit with code 0 or 1, with --bench-out FILE.json for the result; it replaces the key file for the run and puts it back, so use NYREXVJ_DATA_DIR
--netsync-report FILEWrite a JSON report of the network sync when the program ends: role, state, counters, clock, every synced control and a beat sample per frame
--run-seconds NClose the program after N seconds of real time, for tests
--failover-selftestCheck hot standby in the real engine with a simulated primary (readiness, a held and black output, the automatic takeover, a step down, a clean close, a takeover by hand and a clip that cannot be decoded) and exit with 0 or 1, with --bench-out FILE.json for the result; it uses a temporary data folder
--failover-report FILEWrite a JSON report of hot standby about twice a second and when the program ends: state, readiness checks, measured times and events
--failover-takeover-at NAsk for a takeover by hand N seconds after the start and confirm it 0.7 seconds later, for tests

#Tests and measurements

There are options that run self tests and benchmarks and then exit, for example for shaders, outputs, recording, live sources, the web interface and the 3D player. They are described in the README and in docs/TESTING.md of the project. Options that need a value take it as the next word.
