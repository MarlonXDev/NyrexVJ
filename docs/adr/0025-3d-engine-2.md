# ADR 0025: 3D Engine 2.0: skinning, morph targets, blended transparency, Meshopt and optional Draco, limits

- **Status:** Accepted (2026-11-24, requested by MarlonXDev), implemented in v0.32.0. Issue [#76](https://github.com/MarlonXDev/NyrexVJ/issues/76).
- **Date:** 2026-11-24
- **Owners:** Maintainers (pending assignment)
- **Related:** [SCENE3D.md](../SCENE3D.md), [ADR 0001](0001-native-3d-runtime.md), [ADR 0004](0004-scene-document-and-clip-pack.md), [ADR 0005](0005-pbr-shading.md), [ADR 0006](0006-clip-creator.md), [DEPENDENCIES.md](../DEPENDENCIES.md)

## Context
The request asks to extend the glTF/GLB renderer and the Clip Creator with skinning, morph targets, Draco and Meshopt import (as optional dependencies) and correctly sorted alpha blending, to check glTF lights and cameras without harming existing scenes and PBR materials, to limit model size, bones, textures and video memory, and to add test assets, compatibility tests and render benchmarks. Low processor, graphics card and video memory load and stable frame times next to VRChat have priority, and old presets, interfaces and `.nyxclip` files must keep working.

## Findings (what existed before)
- **Loader.** `.glb` and `.gltf` with an allow list of required extensions; skins, morph targets, lights and cameras were ignored with a warning, sparse accessors were refused, Draco and Meshopt files were refused by name, and `alphaMode` `BLEND` was drawn opaque with a warning.
- **Renderer.** One shared vertex shader for the classic and the PBR program, a depth buffer shared by all scenes, geometry uploaded once per model and released from the processor afterwards, nodes evaluated on the processor into a list of instances.
- **Limits.** Vertices, indices, nodes, meshes, animation keys, image sizes and file sizes were limited; nothing limited bones, morph data or the video memory of a whole scene.

## Decision
1. **Skinning runs on the graphics card.** The processor evaluates the joint matrices (`world of the joint node x inverse bind matrix`) once per skinned node and frame and writes them into one RGBA32F texture (four texels per joint). The vertex shader reads four influences per vertex (`JOINTS_0` as `uvec4`, `WEIGHTS_0` as normalized unsigned shorts) from a second vertex buffer. A skinned mesh is drawn with an identity model matrix, as the glTF specification says. A texture was chosen over uniform arrays or a uniform buffer because it has no size limit that a crowd of figures could hit and needs one upload per frame, not one per draw.
2. **Morph targets run on the graphics card too.** Position and normal deltas are stored once per mesh in one RGB32F texture (two texels per vertex and target). A mesh may have up to 32 targets and each draw applies the **eight strongest weights**, so the cost of a draw is bounded and a file with more active targets degrades gracefully. Default weights come from the mesh and the node, animated weights from a `weights` channel; for a mesh with both, the morph is applied first and the skin second.
3. **Blended transparency** is drawn in a second pass after all opaque and masked geometry, depth test on, depth write off, sorted back to front per mesh instance (the distance of the instance centre, for a skinned mesh the average of its joints), double sided meshes back faces first. Sorting per triangle, order independent transparency and weighted blending were rejected: the first costs processor time on every frame and would need the geometry kept on the processor (the geometry is released after upload on purpose), the others need additional render targets and blend modes that OpenGL 3.3 on weak graphics cards handles badly. The known limit is that overlapping triangles of one blended mesh are not sorted among themselves. Opaque and masked drawing is the same code as before.
4. **Compression.** `EXT_meshopt_compression` is decoded on the buffer views before any accessor is read, with the decoder of meshoptimizer 1.3 (MIT, a few small source files compiled into the program, CMake option `NYREXVJ_MESHOPT`, **on** by default, +160 KiB of program size). `KHR_draco_mesh_compression` is decoded on the primitive with Draco 1.5.7 (Apache 2.0, CMake option `NYREXVJ_DRACO`, **off** by default, a further +356 KiB and a long compile, not fetched unless asked for). Without a decoder a file that requires it is refused with a message that names the option; a file that only lists the extension and carries plain accessors or a fallback buffer (`gltfpack -cf`) still loads. Both decoders are bounded by the same limits as plain data.
5. **Limits** (all in `GltfLimits` and `scene_model.hpp`): 64 skins, 128 joints per skin, 32 morph targets per mesh, 1024 joints per frame for all figures together (a figure beyond that is skipped, counted and logged once, the others play), 128 MiB of morph data and 640 MiB of video memory per scene (estimated, checked when loading, in the Clip Creator and again before the upload; a skin costs about 24 bytes per vertex, a morph target 24 bytes per vertex).
6. **glTF lights and cameras are read, counted and not applied.** Up to 16 of each are stored in `Scene::fileLights` and `Scene::fileCameras` and shown in the library details. Applying them automatically would change how every existing model with such data looks and would fight with the lights, sky and cameras of the Clip Creator. A later step can offer them as a choice.
7. **Old scenes stay as they are.** The built-in scenes, models without the new features and `.nyxclip` files take the same code path with the same shader results. This was checked by rendering all seven built-in scenes at three times with the old and the new program and comparing every pixel (21 of 21 identical, Mesa software renderer).
8. **A renderer self test with pixels.** `NyrexVJ --scene-selftest FOLDER` draws the test models through the real renderer into an offscreen target and checks the pixels (a bent arm changes the picture, a morph weight changes the height, only eight morph weights apply, the same two blended planes in both file orders give the same picture and tint the wall behind them, lights and cameras in a file change nothing, 576 figures hit the joint limit with the right count, Meshopt and Draco copies look like the original, built-in scenes draw twice the same). It runs in the Linux CI together with a build with Draco and a build without Meshopt and Draco, which check the refusal messages. It found a real bug that the unit tests could not see: after the upload the processor copy of the joints and morph targets is released, and the evaluation used those lists to decide whether a mesh is skinned, so every figure would have stood still in the real program. The decision now travels in two small fields of the mesh (`keptSkin`, `keptTargets`) and a test releases the data and evaluates again.

## Not changed, and why
- **Tangents, second UV set, texture transforms and other material extensions** were not asked for and stay as they were.
- **Morph target tangents and colours** are ignored (position and normal deltas are used).
- **Spot lights** from a file are stored as point lights with a note, since the scene has no spot light.
- **Prompt 32 (new geometry generation)** is a separate request and was not touched.

## Test assets
All files are in `tests/data/models` (about 2 to 7 kB each, 20 files). `scripts/make_test_models.py` writes the plain models (a two-joint arm, a morphing cube, a sparse morph, a skinned and morphed arm, a cube with twelve targets, two blended planes in both orders, lights and cameras, a model that requires lights), `scripts/make_meshopt_models.sh PATH_TO_GLTFPACK` makes the Meshopt copies (exact floats, quantized, and one with a fallback buffer) with gltfpack 1.3, and `scripts/make_draco_models.py` with `scripts/draco_pack.cpp` makes the Draco copies with the Draco 1.5.7 encoder. The plain models and the Meshopt copies were checked with the Khronos glTF validator (no errors; the one warning of the two skinned plain models is on purpose, their skinned node carries a transform that must be ignored, and the others come from the node layout of gltfpack and of the Draco packer).

## Consequences
- Files with characters and blend shapes from common tools play, and a single mistake in such a file cannot take more than the documented memory.
- The program grows by about 160 KiB (Meshopt) and, only in an opt-in build, by about 356 KiB more (Draco).
- Costs that were measured with a software renderer only: see [SCENE3D.md](../SCENE3D.md) and the changelog. There is no figure for a real graphics card, for Windows at run time or next to VRChat.

## Alternatives considered
- **Skinning on the processor.** Simple and driver proof, but costs processor time for every vertex of every figure every frame, which is exactly what has to stay free next to VRChat, and it would need the geometry kept in memory.
- **Joint matrices in uniform arrays.** At most a few dozen bones per draw on the weakest drivers and one upload per draw.
- **Draco on by default.** Large, slow to compile and rarely used in VJ models; Meshopt is smaller and decodes faster.
- **Applying glTF lights and cameras automatically.** Changes existing scenes; see decision 6.
