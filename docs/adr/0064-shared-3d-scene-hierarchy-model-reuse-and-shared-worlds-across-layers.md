# ADR 0064: Shared 3D scene: object hierarchy, reused models and shared worlds across layers

- **Status:** Accepted for the object hierarchy, the reuse of a model, the shared worlds across layers, the culling and the switch, requested by MarlonXDev (2026-11-27 20:32, prompt 45): a real shared 3D scene in which several models and procedural objects live in one world coordinate system, with a common camera and lighting and correct mutual occlusion, optional and without breaking clips, decks, effects or projects. Physics, collisions, ray casts, constraints and trigger interfaces are **not built** (the request excludes physics); cross-layer transparency is not blended and is an open question (below).
- **Date:** 2026-11-28
- **Owners:** Maintainers (pending assignment)
- **Related:** [SCENE3D.md](../SCENE3D.md), [INTERFACES.md](../INTERFACES.md), [PERFORMANCE.md](../PERFORMANCE.md), [TESTING.md](../TESTING.md), [ADR 0004](0004-scene-document-and-clip-pack.md) (the scene document and the clip pack), [ADR 0005](0005-pbr-shading.md) (lights and sky), [ADR 0006](0006-clip-creator.md) (the editor), [ADR 0025](0025-3d-engine-2.md) (skins, morphs, transparency), [ADR 0062](0062-audio-reactive-3d-materials-sources-and-targets-for-scene-bindings.md) (music on materials), [ADR 0063](0063-virtual-camera-glide-roll-offsets-and-gltf-cameras-for-3d-scenes.md) (the camera the owner of a world uses)

## Context
- State at main `78f8f6c` (0.69.0), as an inventory:
  - **VORHANDEN:** a scene document holds up to 64 objects (a primitive or a model, each with a transform, a material, animations and audio bindings). They are built into one scene and drawn in one pass with one view, one projection and one depth test, so objects of one clip already hide each other correctly. Clips, decks, layer effects, blend modes and the master chain work on the layer texture a scene is drawn into.
  - **TEILWEISE:** the 3D renderer has one depth renderbuffer that every scene layer uses. That is one **resource** that is reused, not a depth buffer that is shared: it is cleared before each layer is drawn, so the geometry of one layer never meets the geometry of another. Two scene layers are two pictures stacked by the blend mode, and the upper one always covers the lower one.
  - **NICHT GEFUNDEN:** a parent for an object (every object is a root, so a hand cannot follow an arm), a way to use the same model twice without storing and uploading its geometry twice, any culling of instances outside the view, and any way to draw two layers into one space.
- Not part of this change, by the wording of the request: physics, collision, ray casting, constraints and trigger interfaces.
- The audio bindings, the animations and the camera of ADR 0062 and 0063 are per clip. They had to stay per clip: two layers in one world keep their own music rows and their own animation time.

## Decision
1. **Hierarchy in the scene document.** An object has an `id` (up to 24 characters of `A-Z a-z 0-9 _ -`, "o1", "o2" and so on when none is given) and a `parent` (the id of another object). A child is built under its parent's node, so it takes the parent's move, turn and scale and the music reactions the parent got (the rule of ADR 0062 for child nodes now has something to apply to). Up to 8 levels. A parent that does not exist, is the object itself, forms a loop, is nested too deep or is missing at build time is cleared, the object goes to the top level and the notes (and the log) name it; the scene plays. A hidden parent hides its subtree. Deleting a parent moves its children to the parent of the deleted object; duplicating an object gives it a new id and the same parent (no subtree copy). The document is written as `"version": 4` only when an object has a parent; `id` and `parent` are written only then. A file without hierarchy stays version 1, 2 or 3 and is byte for byte the old file; a future version 5 is refused.
2. **A model that is used twice is built once.** When several objects name the same model file, `buildSceneFromDoc` adds its meshes, materials and images to the scene once and creates the nodes, skins and animations per use. The vertex limit counts the geometry once. The picture is the one an unshared build draws. This is not GL instancing (there is one draw call per mesh per object, as before); it saves the CPU copy and the GPU buffers.
3. **Shared worlds across layers.** A layer can be set to Own scene (0, the default and the old behaviour) or to World 1 to 4. Layers in the same world are drawn into one space with one depth buffer:
   - The **owner** is the lowest visible layer of the world, the first one drawn. It sets the camera, the lights, the sky and the exposure and **clears** colour (alpha 1) and depth of the world's depth buffer. A **member** clears only its colour (alpha 0) and keeps the depth that is already there; it draws with the owner's view and projection and, for PBR shading, the owner's lights and sky. Each layer is still drawn into its **own** texture, so the layer effects, the blend mode, the opacity and the master chain work on every layer as before, and a Normal blend of the member over the owner gives the picture of one joint scene wherever the geometry is opaque.
   - A member is **placed** relative to the owner with `T(ownerCentre + offset * ownerRadius) * Ry(yaw) * S(scale * ownerRadius / memberRadius) * T(-memberCentre)`: World position X, Y, Z (minus 4 to 4 owner radii), World turn (minus 180 to 180 degrees) and World size (0.1 to 4, in owner radii, log slider). The owner moves the same way relative to the camera.
   - Each world in use has its own depth renderbuffer and framebuffer, at most 4, so two worlds do not see each other. A depth buffer that no layer used for 180 frames is freed.
   - The order stays explicit: 3D draw (shared depth) -> layer effects -> 2D composite in layer order -> master chain. The effects see the layer's own colour; they never see the depth of the world.
   - **Fallbacks, none of them a crash and none of them written to the log:** a member whose target size differs from the owner's draws on its own, a hidden or bypassed layer does not take part (and cannot be the owner), a scene that is not ready or failed to load does not take part (a broken owner leaves the others on their own), and the switch off draws every layer on its own. The layer is then an ordinary layer; the only sign is the picture.
   - Each layer keeps its own scene, its own animation time and its own audio bindings; only the camera, lights, sky, exposure and the depth are common.
4. **Culling.** For every instance that is not skinned and has no Inflate, Ripple or morph target, the bounding sphere (mesh radius times the largest axis scale of the model matrix, 2 percent and a small constant of margin) is tested against the six planes of the view frustum, and an instance outside is not drawn. It is conservative: the 21 built-in picture cases and four models draw the same bytes with it on and off.
5. **Controls and files.** Four layer controls, `layer/N/world-x`, `world-y`, `world-z` and `world-yaw` (the world number and the size are choices, not controls), so MIDI, OSC, the web interface, macros and the Show timeline lanes can move a layer in its world. A layer is written to a preset with `world`, `worldX`, `worldY`, `worldZ`, `worldYaw` and `worldScale` only when they differ from the default; values are clamped on load. Settings, Performance, **Shared 3D worlds**, on at the start, written to `settings.json` only when off.
6. **The editor.** The Clip Creator lists objects indented under their parents, has a Parent drop-down for each object (only objects that would not make a loop or exceed 8 levels are offered), shows ids, and moves, duplicates and deletes with the rules above. The Layer panel of a scene clip has a Shared 3D world section (World and the five sliders).
7. **A demo.** `docs/examples/shared-3d-world/` has two clips that overlap in space (an arm and a cube), a `.nyxclip` that uses a parent and the same model twice, and a preset `Shared 3D World.json` that puts the two clips in World 1 on two layers.

## Alternatives considered
- **One scene graph for the whole composition**, merging all scene layers into one scene every frame. Rejected: the layers have different clips, animation times and audio rows, they would have to be copied or re-evaluated into one list every frame, and the layer effects (which work on a layer's own picture) would have to run on a part of a shared picture.
- **One colour target and one depth buffer for all layers of a world, drawn together, and then split per layer.** Rejected for the same reason: the layer effects and the blend mode need a picture per layer.
- **Reusing the depth renderbuffer of the old renderer and calling it shared.** That is the thing the request warned about: the resource was shared and cleared every draw, the depth was not.
- **Sorted, blended transparency across layers.** Needs the transparent triangles of all layers in one sorted list or an order-independent pass, and it conflicts with the layer effects between the layers. Not built; see the open question.
- **Real GL instancing for a reused model.** The transform, skin and material of each use differ and the scenes are small; the saving is memory, not draw calls. Not built.

## Measured
All values come from `nvj_world_tests`, `NyrexVJ --scene-selftest tests/data/models`, `scripts/test_shared_world.py` and the full `ctest` on Linux with Mesa llvmpipe (software OpenGL on the processor, two cores, one machine, not a graphics card).
- Unit tests: `nvj_world_tests` is new, 840 checks, 0 failed. They cover the ids and their repair, the parent rules (self, missing, loop, too deep, hidden parent, delete, duplicate), the version written (1, 2, 3 or 4) and the refusal of 5, a round trip through JSON and through a clip pack, transform inheritance against a hand-baked transform, music inheritance (a child takes its parent's reaction), the reuse of a model (same picture, half the vertices), the placement matrix, the frustum test, the limits and bad numbers of the layer fields, the preset keys and the control ids.
- Render tests: the scene self test has 23 new checks and passes 102 of 102. An owner alone draws the same picture as an isolated scene (same hash). A member in front of the owner and behind it each give the picture of one scene drawn together, differing share 0.00 percent. Occlusion comes from the depth and not from the layer order: the green object has 41,628 pixels when it is in front and 2,712 when it is behind, with the same layer order. Two worlds do not see each other (38,630 lit pixels, as if alone). Two worlds of 256 x 256 hold 524,288 bytes of depth (2 x 256 x 256 x 4), the sum is part of the 3D depth total and an idle world is freed (0 bytes). A member with another resolution and a broken owner fall back to their own scenes. Each layer keeps its own music rows (with the same music in both layers, the member that has a Kick row grows from 7,271 to 24,131 lit pixels and the one without stays small). Culling skips 26 of 40 instances (14 drawn) in a wide scene; the 21 built-in picture cases at three zoom levels and four models (a skinned arm, a morph cube and a blended mesh among them) are byte for byte the same with culling on and off.
- Model reuse: a model used twice has 24 vertices and 2,448 bytes of graphics memory, a copy per use has 48 and 4,896.
- The engine: `scripts/test_shared_world.py` renders the demo preset through the real program with worlds on, off and with the old layout without a world (9 checks, all pass). With World 1 both layers show (13,608 salmon and 78,021 blue pixels) and the object in front covers part of the other by depth; without a world the upper layer covers the lower (48 salmon, 71,223 blue pixels, the old behaviour); the switch off gives the picture of layers without a world.
- Same picture as 0.69.0: the hashes of the 7 built-in scenes at 3 times in the editor path and in the camera path and of the 12 music moments are the same in a 0.69.0 build and in this one.
- Mutation probes (a fault put in, then reverted): 8 faults, 6 for the unit tests (the placement ignoring the owner radius, the far plane of the frustum, a child not linked to its parent, a hidden parent not hiding the subtree, model reuse off, the loop repair off) and 2 for the renderer (a member clearing the depth, a culling radius that is too small). All 8 were caught at once, each by a check that names the fault.
- Full `ctest`: 70 of 70 tests pass.
- Cost: four layers of the same scene at 256 x 256, average milliseconds per frame, one run each: 63.42 isolated and 41.11 in one shared world. One run on a software rasteriser says that sharing the depth is not slower; it does not say that it is faster, and no speedup is claimed.
- By hand: nothing in the interface was clicked through for this release (see below).

## Not done
- **Physics, collision, ray casting, constraints and trigger interfaces.** The request excludes physics; objects have no volume for anything but drawing.
- **Cross-layer transparency.** A translucent surface blends with what is behind it inside its own layer only. Between layers, the usual layer blend mode applies on the layer texture, so a translucent surface in a member layer does not blend with the owner's geometry by depth.
- **GL instancing**, **duplicate with subtree** and **a camera of its own for a member** (a member uses the owner's camera; its own camera and Zoom are ignored in a world).
- **Different resolutions in one world** (the member draws on its own).
- **Classic shading in a world.** The classic-shaded built-in scenes keep their fixed lights in a world; only PBR scenes take the owner's lights and sky.
- **A real graphics card, Windows at run time (built in CI only), a long show with four worlds, MIDI and OSC mapping of the new controls on hardware, the network sync of the new layer fields between two instances (the schema changed; the unit tests pass, two instances were not run), and the new sliders and the Parent drop-down dragged and clicked by hand.** See `M-WLD-1`.

## Open questions for the maintainer
- **Who owns a world?** Now it is the lowest visible layer of the world, which changes when a layer is hidden. An explicit "this layer is the owner" choice would be steadier and needs one more field.
- **Should translucent surfaces blend across layers?** It needs a sorted pass over all layers of a world and a decision about where the layer effects go in that case.
- **Should the classic-shaded built-in scenes take the owner's lights?** They would look different in a world than alone.
- **Should members keep their own camera or zoom?** A world has one view; a member that zooms on its own would no longer sit in the same space.

## Consequences
- `Layer` has six new fields, `SceneDoc` objects have `id` and `parent`, `Settings` has one new field and `settings.json` one optional key; older programs ignore them.
- The control list has sixteen more ids (`layer/1..4/world-x`, `world-y`, `world-z`, `world-yaw`), each group after `camera-fov` of its layer. No id was renamed or removed, so OSC, MIDI and the Unreal plugin keep working. Ids after the new ones moved in the list, and the 64 bit schema hash of the network sync, which is made from the ids, has changed: a master and a follower on different versions around this release only exchange the clock until both are updated.
- A scene without a parent is written exactly as before. One with a parent is version 4 and 0.69.0 and older refuse it with the existing message. A preset has the world keys only when a layer uses them.
- The depth memory of a world is part of the 3D depth total in the graphics memory report.
- Not run on a real graphics card or on Windows beyond the CI build; see `M-WLD-1`.
