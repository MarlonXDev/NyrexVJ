# ADR 0030: ISF import as a translation into the Shader 2.0 plan: one renderer, controls from the file, image filters as effects, hard limits and visible notes for what is not supported

- **Status:** Accepted (requested by MarlonXDev, Prompt 07). Issue [#86](https://github.com/MarlonXDev/NyrexVJ/issues/86). ISF vertex shaders, ISF transitions, audio inputs, cube maps, driving the controls of a clip with audio, LFOs, MIDI or OSC, an editor in the program and a file picker for imported pictures are **Proposed** and wait for the maintainer.
- **Date:** 2026-11-25
- **Owners:** Maintainers (pending assignment)
- **Related:** [SHADERS.md](../SHADERS.md), [INTERFACES.md](../INTERFACES.md), [TESTING.md](../TESTING.md), [ADR 0017](0017-node-effect-editor.md), [ADR 0022](0022-glsl-shader-2.md), [ADR 0027](0027-live-stability-and-hardware-test-matrix.md)

## Context
The request: import ISF (Interactive Shader Format) files as image filters and as generators, with metadata, parameters, defaults, input pictures and suitable multipass functions; use the multipass path of Shader 2.0 (ADR 0022) and do not build a second one; show what is not supported; safe parser limits, a fallback when a shader fails, example shaders and compatibility tests.

## Findings (what existed before)
- **One shader path.** `prepareShaderSource` (`src/render/shader_source.cpp`) cleans a file, finds the style (NyrexVJ or Shadertoy), reads the `#pragma nyrexvj` directives and returns a `ShaderPlan` (passes, buffers a to d, four channels per pass, alpha). `clip_library.cpp` assembles the GLSL of each pass, `Engine::runShaderPasses` draws the plan with RGBA16F ping pong buffers inside a 512 MiB budget, errors name the pass and the line of the file.
- **No parameters.** A shader clip had no controls of its own, only the layer controls and effects. A `ClipPlayback` per cell (speed, in and out points and so on) existed and is stored in presets only when it differs from the default.
- **Effects are separate.** The effect list holds the built in effects (one GLSL body with `uTex`, `uPrev`, four controls and `uMix`) and the node graphs of the Node editor (ADR 0017). Neither can have several passes or its own buffers, and neither reads files from the shaders folder.
- **Node editor.** It makes effects from a graph of nodes, written to `nodes/<name>.nyxfx`. It has no text shader node and no import path for GLSL or ISF; adding one would be a different feature.
- **No ISF code anywhere**, and the documentation said ISF import was planned separately.

## Decision
1. **Translate, do not add a renderer.** `translateIsf` (`src/render/isf.cpp`) turns an ISF file into the text of a Shader 2.0 file plus the new directives below, and `prepareShaderSource` parses that as it parses every file. Buffers, the budget, the release of buffers, the thumbnails, hot reload, the error text and the fallbacks are the code that already ran in ADR 0022. A file without an ISF header is compiled exactly as before (the old fingerprint test still holds).
2. **Fragment shader only.** ISF files are GLSL 1.20 era fragment shaders with optional vertex shaders. NyrexVJ reads the fragment part, rewrites `gl_FragColor` and `void main`, and defines `TIME`, `TIMEDELTA`, `FRAMEINDEX`, `RENDERSIZE`, `PASSINDEX`, `isf_FragNormCoord`, `IMG_PIXEL`, `IMG_NORM_PIXEL`, `IMG_THIS_PIXEL`, `IMG_THIS_NORM_PIXEL`, `IMG_SIZE` and `texture2D` as macros over the Shader 2.0 names. Old OpenGL and vertex features (`varying`, `attribute`, `isf_vertShaderInit`, `gl_TexCoord`, `gl_Vertex`, the old matrices, `ftransform`, `sampler2DRect`) are refused with the first name found; they cannot be translated without a vertex stage.
3. **The body keeps its line numbers.** The header comment is kept in front, helper lines are inserted after it and followed by `#line K`, so a compiler error shows the line of the ISF file. The wrapper `void main() { isf_PassIndex = N; isf_main(); }` is added after the body, once per pass.
4. **Four new generic directives**, usable in hand written files too: `plain` (only the uniform declarations, none of the helper functions `PI`, `hash21`, `rot`, which would clash with ISF code), `filter` (the file is an effect and not a clip), `param name kind "Label" ...` (float, int, bool, point, color, list) and `channel N picture` (a filter reads the picture of its layer). All are checked with line numbers like the existing directives.
5. **Controls.** `param` lines (written by the translator for ISF inputs) give at most 8 controls and 16 numbers per file. The uniforms are declared by NyrexVJ. For a clip, the values live in `ClipPlayback::values` (16 floats, a sentinel for "use the default of the file"), so the same shader in two cells can have two settings, and a presets entry gains a `values` list only when one was changed (null for a default). The Clip window draws one widget per kind. A value that was never touched follows the default of the file. Inputs beyond the limits are baked in as constants with their default, and the Clip window says so.
6. **Filters are effects.** An ISF file with an input named `inputImage` is a filter. It is listed as `ISF: <file name>` in the effect list and not in the Library. The picture of the layer is bound as `uPicture` and as the `picture` channel; the result is mixed with it by `uMix`, which is the strength of the effect (so the audio gate works). The first four scalar controls (float, int, bool, list) are the four controls of the effect, with the labels and defaults of the file, so presets, audio reaction, LFOs and macros work like for any effect. The buffers of a filter belong to the effect slot (one state per slot, freed after 240 idle frames, counted in the same budget). A broken filter passes the picture through and shows its error in the effect panel.
7. **Passes.** `PASSES` entries with a `TARGET` become buffers a to d in order, the last entry (without a `TARGET`) is the shown picture. Buffers are always kept between frames and always RGBA16F, so `PERSISTENT` and `FLOAT` need no switch. `WIDTH` and `HEIGHT` are evaluated by a small expression evaluator (numbers, `$WIDTH`, `$HEIGHT`, names of float inputs, `+ - * /`, brackets, `floor`, `ceil`, `round`, `abs`, `min`, `max`; no recursion beyond the 128 byte limit) at two sizes; a result that is a fixed share of the picture becomes the buffer scale (from 0.25 to 1), anything else uses the full size and a note says so.
8. **Imported pictures and other inputs.** `IMPORTED` entries read the Library picture `Image: <file name without ending>`; the path of the ISF file is never opened, so `../` and absolute paths cannot reach a file. Inputs that have no source here (audio, audioFFT, other image inputs, cube maps) read transparent black; events are switches that are never pulsed; `DATE` is a constant. Every one of these puts a line into the "Notes about this file" list of the Clip window or the tooltip of the effect.
9. **Limits when reading.** Header at most 64 KiB, nesting at most 12 (checked before the JSON parser sees the text), 64 inputs, 16 passes, 8 imported pictures, 8 categories, texts 512 bytes, numbers within ±1,000,000, names up to 32 valid GLSL identifiers that are not reserved by GLSL 3.30, ISF or NyrexVJ, a file up to 256 KiB as before. The JSON is parsed as data; an exception becomes a message with the line inside the header. The header is never run.
10. **Examples and tests.** Five example files in `docs/shaders/`, `nvj_isf_tests`, 54 new checks in `--shader-selftest`, five new benchmark cases, a section in SHADERS.md that lists what works and what does not, and an area in the hardware test matrix.

## Alternatives considered
- **A second ISF renderer next to the Shader 2.0 code.** It would duplicate buffers, budget, release, error and hot reload code, and the request says not to. Translation costs a text pass per file and needs no new draw code.
- **Using the existing Shadertoy style as the target and mapping `inputImage` to `iChannel0`.** Shadertoy style has no controls, no filters and no buffers beyond four with the Shadertoy order rules; ISF passes read their own targets in any order. Using the NyrexVJ style with explicit directives is closer.
- **Making a filter a clip that reads the layer below.** It would not use the effect rack, its strength control or the audio gate, and could not sit between two effects.
- **Binding `values` to the effect controls for clips.** The four controls of an effect are 0 to 1 and rank by slot; a clip has its own range per control (colour, point, list) and up to 16 numbers.
- **A node in the Node editor for ISF.** The Node editor writes `.nyxfx` files from a graph; ISF files are text files that people edit outside the program. A node would need its own passes and buffers.
- **Rejecting a file on the first note-worthy feature.** Many real files have one audio input or a few more inputs than fit. Running them with a note is more useful than refusing; only features that would make the picture wrong without a clear reason (vertex code, transitions, too many buffers or pictures) are refused.
- **Renaming input names that GLSL reserves** (`filter`, `input`, `smooth` and so on) with macros. It would work, but then the control names in the file and in the shader differ and the error text would show other names. A refusal with the name is clear and a one word fix.

## Consequences
- An ISF file costs the same per frame as a Shader 2.0 file of the same shape; the translation runs when the file is read (the test runs 22,699 translations of the five examples and of damaged variants in 0.75 s).
- The clip library keeps filter files out; the effect library gains up to 64 `ISF:` entries. `refreshIsfEffects` looks at the folder once a second like `refreshShaderClips` and caches what it has already read by size and time, so files that are no filters are not read again each second.
- Presets store a filter by its effect name, `ISF: <file stem>`. Renaming the file makes an old preset lose the effect (the same as for node effects).
- The controls of a clip can be set by hand only. They have no control ids, so OSC, MIDI, the cue list, the web interface and automation cannot move them yet; the four controls of a filter can, because they are effect controls. This matters for Prompt 08 (show timeline), which must not assume more.
- `ClipPlayback` is 64 bytes larger and the playback JSON gets one optional key. Older programs ignore it.

## Validation / open questions
- Done here: `nvj_isf_tests` (22,970 checks: detection, the five examples, the plan and the generated GLSL, 44 kinds of damaged ISF files each with the message expected, 27 kinds of mistakes in `param` lines, buffer size expressions, the unsupported list, resolve and control conversion, the preset round trip with hostile values, and 22,699 truncated, mutated and random inputs), all 33 test groups of the suite, `--shader-selftest` through a real OpenGL context (94 checks, 54 of them new: ISF generators with defaults and stored values per cell, a colour, a bool and a list value, a persistent half size buffer and its memory, an imported picture, filters in the effect rack, the first control, the strength gate, a two pass blur, a persistent filter buffer, a broken file next to a working one, an unsupported file, a broken filter, hot reload of a generator and a filter, a removed filter, and the five examples), AddressSanitizer and UndefinedBehaviorSanitizer for the parser tests, and the frame time and memory comparison against the previous release in [SHADERS.md](../SHADERS.md).
- **Not done:** any graphics card (all runs used the Mesa software renderer), Windows beyond the CI build and the unit tests, the files of other ISF programs in bulk (only five written for this change were rendered; a larger corpus is a manual test in the matrix), a comparison of the pictures with VDMX, Resolume or another ISF host, VRChat, projectors.
- Open for the maintainer: audio inputs for ISF (which of the NyrexVJ audio sources they should read), ISF transitions, an ISF vertex path, whether the controls of a clip should get control ids (OSC, MIDI, cues, API), a file picker for imported pictures, and the effect name prefix for filter files that are not ISF.
