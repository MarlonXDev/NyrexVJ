# Changelog

## 0.25.0 - 2026-11-21

- Node effect editor: build your own effects from nodes. Creator, Node effect editor (or Edit nodes under a node effect in the rack, or `--node-editor`) opens a graph editor drawn with the existing Dear ImGui draw list, so there is no new library. Right click adds a node (with a search), dragging from a pin connects, a connected input dragged away removes its link, values are dragged or typed (double click or Ctrl+click), and there are undo and redo, duplicate, delete, an Arrange button and a status line that says whether the effect compiles. The effect is saved 0.35 s after the last change and rebuilt. There is no zoom.
- 68 nodes in nine categories: inputs (picture, previous picture, UV, centred UV, time, beat, audio, spectrum, waveform, control, macro, LFO and constants), maths, vector, colour (hue, saturation, brightness and contrast, invert, rainbow palette, five blend modes), distortion (rotate, zoom, move, mirror, kaleidoscope, swirl, wave, pixelate, polar, tile, lens, sample), noise, shapes, a blur with 2 to 16 samples, an edge detector and the Output node. Ports are Number, Vector 2, Colour and Colour with alpha; a number feeds any vector or colour, and nodes such as Add or Mix take the widest type of their inputs.
- Graph to GLSL compiler: a graph is checked as a whole (an empty graph, more than 96 nodes or 256 links, unknown nodes, a missing or second Output, an input with two links, loops, types that cannot be combined, more than 64 picture reads) and turned into one shader, so a node effect is one draw like an effect written by hand. Nodes that do not lead to the Output are not emitted. The shader is cached by a hash of its text, so moving nodes causes no rebuild. An error is shown on the node that causes it, and an invalid edit keeps the last good shader running instead of showing a black picture.
- Controls, macros and the beat: every effect has four controls with labels and defaults that Control nodes read, a Macro node reads one of the eight composition macros (so MIDI, OSC and modulation can drive a graph), and an LFO node runs in the shader on the beat clock with a sine, triangle, saw or square shape of 0.25 to 64 beats. A number typed into an unlinked input is part of the shader and rebuilds it; controls, macros and the LFO are uniforms and do not.
- Effect files: an effect is a small `.nyxfx` file (JSON, format `nyrexvj-effect`, version 1, at most 256 KiB) in the `nodes` folder of the user data folder, and appears in the library as `Node: <name>` after the built-in effects, up to 64 of them. Four examples (Wavy Rainbow, Mirror Swirl, Kick Pulse, Trails) can be created with one button; files can be imported (also by dropping them on the window), exported to any path, duplicated and deleted, and a file cannot contain shader code, only catalogue nodes and numbers. A preset stores the effect name; if the file is missing the preset loads without that effect and says so.
- Performance: a graph compiles to GLSL in 8 to 24 microseconds (7 to 13 nodes) and the same graph gives the same text. Against four hand written effects (`--bench-nodes`, software OpenGL, 1920 x 1080) the effect times were within the spread of the runs (ratios 0.91 to 1.17 over three runs, no pair always on one side) and the three pairs without feedback gave identical pixels. Nothing is allocated or drawn for node effects while none is used, and a graph with Previous Picture needs one extra picture buffer.
- New files, tests and texts: `docs/NODES.md`, ADR 0017, a section in `docs/PERFORMANCE.md`, a row in `docs/INTERFACES.md`, `src/core/node_graph.*`, `node_catalogue.cpp`, `node_compile.*`, `node_files.*`, `src/app/ui_nodes.cpp`, `node_editor.hpp` and a test program with 2,382 checks (document, JSON, compiler, files, every catalogue node); `--check-shaders` compiles 129 node graphs with the driver, `--bench-nodes` runs in CI, and there are 39 new texts in German, Spanish and French.
- Known limits: nothing was tried on a real graphics card, with a touch screen or tablet, next to VRChat or on Windows at run time; the compile and the numbers come from a software rasteriser, and the editor was driven by a script, not by a person. There is no zoom, no groups and no comments in the editor. A deleted effect file stays in the library, marked as gone, until the next start. The files have no checksum, the names of nodes, pins and options and the messages of the compiler are English only, and the driver compile time of a large graph was not measured.

## 0.24.0 - 2026-11-21

- One beat clock: everything that follows the beat (effects, clip length in beats, modulation, OSC output, the BPM display of the deck) now reads one clock that several sources can feed: tapping, the audio analysis, MIDI clock, timecode and Pro DJ Link beats. Automatic takes the best source that is present (Pro DJ Link, timecode, MIDI clock, audio, manual) and falls back when it is lost; a fixed choice stays on its source. Phase errors are removed gradually (at most a quarter of the error per observation) so a picture on the beat does not stutter, a jump of more than a beat is followed at once, and a latency offset of -500 to +500 ms moves the beat. The state (Free running, Searching, Acquiring, Locked, Lost), the phase error and the source are shown in the new Settings, Sync page. The old Sync BPM to audio setting works as before.
- Timecode: LTC is decoded from an audio input of its own (24, 25, 29.97 drop frame and 30 frames a second, noise, DC offset, inverted signal, dropouts and speed changes are handled), and MTC is decoded from the MIDI input (quarter frames and full frame messages, with the 1.75 frame correction). The timecode sets the position of the beat clock (`beat = seconds x BPM / 60`), LTC wins over MTC, and the page shows the time, the frame rate, whether it is running and the counts of good and rejected frames. A signal that is lost for half a second is dropped.
- Cues and modulation: a cue list (up to 512 cues, saved as `cues.json`) fires any control target at a timecode time, once each, and skips cues after a jump or a step of more than half a second so a seek does not fire a wave of cues. The Sync page edits the list with a target picker. Timecode second and Timecode minute are new modulation sources.
- MIDI clock: ticks, Start, Continue, Stop and song position are followed. Ticks are time stamped in the MIDI input thread, so the frame rate adds no jitter. The tempo comes from a short window of tick intervals; a Start makes the position known; without a Start only the tempo is used. Measured against a simulator the phase error stays at 0.006 beat.
- Pro DJ Link: a passive listener for the beat packets of Pioneer players and mixers on UDP port 50001, opened shared so other programs can listen at the same time, off by default. It never announces itself and sends nothing, takes tempo, beat in the bar and phase, and shows the players heard and the packet counts (ignored and malformed ones included). Measured against a packet simulator the phase offset is 0.04 beat (beats are stamped when they are read, so the accuracy is one frame). No play state and no master flag are used.
- StageLinq (Denon): evaluated and not built. The protocol is reverse engineered, a device must be announced and reached over several TCP services, and nothing could be tested, so a safe passive subset is not possible. The reasons and what works today (MIDI clock from the mixer, the audio analysis) are in the document. A future source only has to report observations to the beat clock.
- Output frame lock: with several outputs open, all windows are drawn first and then swapped right after each other. The time between the first and the last swap of two 1280 x 720 windows fell from 4.5 to 5.1 ms to 0.34 to 0.35 ms (software OpenGL). Every output has a Delay of 0 to 8 frames for slower projectors; the delay ring is shared, exists only while a delay is set and takes 23.7 MiB and 0.6 ms a frame at 1080p with a delay of 2. The swap skew is measured and shown over 120 frames, and the new Sync bars pattern (binary frame counter, flash, moving bar) shows with one camera how many frames apart outputs are. This is not a hardware genlock.
- New files, tests and texts: `docs/SYNC.md`, ADR 0016, a section in `docs/PERFORMANCE.md`, `src/core/beat_clock.*`, `timecode.*`, `ltc.*`, `midi_clock.*`, `djlink.*`, `cue_list.*`, `frame_lock.*`, `src/control/sync_system.*`, `djlink_input.*`, `src/render/texture_history.*`, `src/app/ui_sync.cpp` and six new test programs (99 checks for the clock, 364 for timecode, 28,185 for Pro DJ Link, 246 for MIDI clock, 48 for the sync system, 130 for the frame lock) plus 29 new checks in `--output-selftest` (93 in all); about 91 new texts in German, Spanish and French. The cost of the sync system without any source is 0.04 microseconds a frame, decoding LTC takes 0.25 ms for each second of audio.
- Known limits: nothing was tried with real Pioneer or Denon gear, timecode generators, audio interfaces, real MIDI clock hardware, projectors, a real graphics card, several graphics cards, next to VRChat or on Windows at run time. 25 fps at 4 percent slower cannot be told from 24 fps, 29.97 non-drop shows as 30, reverse timecode is not supported, a vanished audio device is not reopened by itself, and the Pro DJ Link time is accurate to one frame. All numbers come from generated signals, a packet simulator and a software rasteriser.

## 0.23.0 - 2026-11-21

- Slices: every output can now have up to eight slices instead of one picture area. Each slice has its own part of the picture, corner handles, warp grid, edge blending, brightness, flips, fill mode and mask, and a name. Slices are drawn in order, later ones on top, and are chosen with a bar above the live canvas (Add slice, Duplicate, Remove, name, Show this slice). Other slices are drawn as blue outlines with their names while one is edited. Slice 1 is the old picture area, so old settings load unchanged, and one plain slice is drawn exactly as before (no blending, pixel identical, 42 KB of video memory).
- Masks: a slice can have a polygon mask of 3 to 32 points in output space. Drag points on the canvas, double-click an edge to add a point, right-click a point to remove it, start from the presets Rectangle or Ellipse. Soft edge (up to 25 % of the picture height) and Invert are available, and the mask is tinted green (visible) or red (inverted) on the canvas. A mask is built once when it changes (2.1 to 2.3 ms; a soft mask uses 512 x 288, a hard one 1024 x 576) and sampled as alpha in the shader; a slice without a mask has no texture.
- Colour per output: gain for red, green and blue, saturation, contrast, gamma and black lift for the whole output, in Settings, Output, Colour of this output, with Reset colour. It runs inside the existing output shader and is switched off completely while it is at its default, so it adds no pass, no texture and no cost. The test pattern is not coloured.
- Black level for edge blending: a slice with an edge blend can raise the black of everything outside its blend zones (0 to 30 %), so that the overlap of two projectors, which adds their black, matches the rest of the picture. The zone border is antialiased. This is a simple model and not a calibration against a real projector.
- Warp grids up to 17 x 17 points (was 9 x 9). The mesh follows the grid size (32 divisions up to 9 points as before, up to 128 above), so settings with grids up to 9 x 9 draw as before. Moving a point by much more than one grid cell can fold the picture over itself.
- Venue setups: Settings, Output saves all four outputs (slices, masks, colour, displays, fullscreen) under a name as `venues/NAME.json` in the user data folder. A venue can be loaded, duplicated, deleted (with a question), exported to any path, imported from any path or by dropping a `.json` file on the window, and the command line option `--venue NAME|PATH` loads one at start. A wrong format, a newer version, a file over 2 MiB or a damaged file only produces a message and changes nothing. Names are cleaned for all file systems (also Windows device names) and work with umlauts. Loading does not open windows by itself; windows of outputs that the venue turns off are closed.
- A real output test: `--output-selftest` draws a picture of four coloured quadrants through the real output window and compares pixels for the default slice, several slices, masks, colour, black level and warp (64 checks), and logs frame times and video memory. It runs in CI on Linux after `--live-selftest`. Measured with software OpenGL (llvmpipe, 1280 x 720 window, three runs): one default slice 4.2 to 4.7 ms, with a hard mask 6.6 to 7.1, with colour 7.0 to 7.2, four masked slices 21.4 to 22.5, eight soft masked slices with 17 x 17 warp 61 to 63 ms and 2.5 MB of video memory.
- New files and tests: `src/core/venue_setup.*`, `src/app/output_selftest.*`, `docs/adr/0015-advanced-output.md`, a rewritten `docs/OUTPUTS.md` and a new section in `docs/PERFORMANCE.md`; about 25,000 checks for geometry, masks, colour, black level and JSON, 100 for venue setups, 51 new texts in German, Spanish and French.
- Known limits: nothing was tried on real projectors, with real blending by eye, on a real graphics card, in multi-monitor fullscreen, next to VRChat or on Windows at run time; the numbers come from a software rasteriser. The default path was not compared with 0.22.0 under identical conditions. Colour is per output, not per slice, and slices have no blend modes (later ones simply cover earlier ones). A venue stores display numbers, which can point to a display that does not exist on another computer.

## 0.22.0 - 2026-11-20

- Live sources: eight new clips in the library under the filter Live, NDI Input 1 to 4 and Camera 1 to 4. Put one into a cell and choose the source in the Clip window. A source is opened when a layer shows its clip and closed three seconds after the last use, so an unused source has no thread, no memory and no open device. The choice is saved in the program settings, not in presets, because device and sender names differ between computers.
- NDI input: senders on the network are found in the background and listed, Automatic takes the first sender that is not NyrexVJ's own output, and a named sender that is not there yet is searched for until it appears. Pictures are requested as UYVY (with alpha as UYVA) at the highest bandwidth, only the newest picture is kept and skipped ones are counted. Other formats are shown as unsupported with the reason. The NDI library is still not shipped and is loaded at run time (install the free NDI Tools); the NDI sender now uses the same loader.
- Cameras and capture cards through the FFmpeg device library (Video4Linux2 on Linux, DirectShow on Windows), with a camera list and Refresh, and a requested resolution and frame rate (default 1280 x 720 at 30, Auto leaves it to the device; modes above 640 x 480 at 30 ask for MJPEG first). The device library (`libavdevice`, which needs `libavfilter`) is loaded like the other FFmpeg libraries; without it only the camera clips report that cameras are not available.
- Reconnecting: every source has the states Searching, Connecting, Live, Signal lost and Reconnecting, shown in the Clip window with the size, frame rate, dropped pictures, attempts and latency. After a loss or failed attempt NyrexVJ retries after 0.5 seconds, then 1, 2, 4, 8 and every 10 seconds, and a camera that hangs is cut off by a deadline. The last picture stays on the layer while the signal is gone; the placeholder look is shown only before the first picture.
- Low latency and an efficient upload: pictures travel as packed UYVY (2 bytes per pixel) and are converted to RGB on the graphics card with the right matrix (BT.709 from 720 lines up, BT.601 below), which halves the bytes of an RGBA upload and leaves the conversion off the processor. Measured with a test source and software OpenGL: 1080p at 60 needs 3.1 ms of upload, 12.5 ms from arrival to the end of the upload (95th percentile 14.4 ms), 16.6 MB of video memory and 16.5 % of one core; 720p at 30 needs 2.3 ms, 7.4 MB and 6.9 %.
- New command line options `--live-selftest` (checks the whole live path with a test source, runs in CI on Linux) and `--bench-live SECONDS:camera:SOURCE` or `SECONDS:ndi:NAME`. New files `docs/LIVE.md` and ADR 0014, 429 new checks in three test programs (state machine and slots, NDI receiving against a fake NDI library, cameras with FFmpeg test sources), 22 new texts in German, Spanish and French, and `docs/DEPENDENCIES.md` lists the device library.
- Known limits: nothing was tried with a real camera, capture card or NDI runtime, with DirectShow on Windows, with a real graphics card or next to VRChat; the numbers above come from a software rasteriser and a test source. NDI alpha is assumed to be straight, not premultiplied. The latency shown is measured inside NyrexVJ only (arrival to end of upload), not through camera, cable or network. Please run `--bench-live` on your computer and report what you see.

## 0.21.0 - 2026-11-20

- Media control for video clips: the Clip panel of a video now has a Playback section with time and frame display, a scrub bar that jumps to the exact picture, single frame steps, Play and Pause, In and Out points (with Set here), a loop mode (Loop, Ping-pong, Once and hold the last frame, Once and then disappear), a clip speed from -4x to +4x with a Reverse button, and a clip length in beats that keeps the clip on the tempo of the deck. The settings belong to the cell and are saved in the preset; presets from older versions play as before.
- Reverse playback: HAP and other formats with a key frame at every picture go backwards picture by picture. Other codecs decode a short piece forward into a ring of 6 to 16 pictures (about 96 MiB at most for 1080p) and hand it out backwards. The video monitor shows when a clip plays backwards, how many pictures are buffered and how many seeks happened. Videos with long key frame intervals cost much more processor time in reverse, `docs/MEDIA.md` says what to do about it (HAP, or a short key frame interval).
- Exact seeking: the decoder seeks to the key frame before the wanted picture and decodes up to it, so scrubbing and the In point show the right picture, not the nearest key frame.
- Switching without empty frames: the next filled column of every layer is opened and decoded up to its first picture in the background. Measured with eight 1080p H.264 clips and 16 switches: without it 11 of 16 switches showed an empty frame (47.9 ms on average, 111.2 ms at most until the first picture), with it none and the picture was there in the first frame. It costs about 14.5 MB of video memory per prepared 1080p clip and one decoder per layer. Settings, Performance, Prepare the next clip of every layer turns it off, `--no-prewarm` does it for one run.
- New command line option `--bench-switch SECONDS:CLIP1,CLIP2,...` to measure clip switches.
- New files: the play head as its own piece of code without FFmpeg or OpenGL (`src/core/playhead.*`, 101 unit checks), the driver between layer clock and decoder (`src/media/playback_driver.*`), two index test videos where every picture carries its number, and ADR 0013.
- Fixed: two checks of the test suite failed when the user data folder contained images or videos, because they expected shader code in every clip. Image and video clips are now excluded from that check.
- Known limits: a clip that runs in several layers at once shares one decoder, so different positions or directions of the same file in two layers are not possible (use a copy of the file). Ping-pong and backwards loops restart the reverse piece at the turning point, which can stutter on a slow decoder. Everything was tested with software decoding and software OpenGL; hardware decoding in reverse, real graphics cards, VRChat and Windows at run time were not available for the test.

## 0.20.0 - 2026-11-20

- Linux release: every build now also produces `NyrexVJ-linux-x64` (one file) and `NyrexVJ-linux-x64.tar.gz` (with licenses, changelogs and the list of libraries). The program is built on Ubuntu 22.04 with libstdc++ linked in, needs only libc and libm, runs on glibc 2.35 or newer and uses X11 or XWayland. CI checks the library list and the glibc version of every build, so a new dependency cannot slip in unnoticed.
- Audio on Linux: system audio (everything the PC plays), the default input and every PulseAudio or PipeWire source can be chosen in the Audio tab, loaded at run time without a build dependency. A missing sound server shows a clear message and the demo signal keeps working. Checked against a real PulseAudio server and a fake library; PipeWire itself was not available for the test.
- MIDI on Linux: controllers that show up as ALSA sequencer ports can be added and learned like on Windows, and are listed with duplicate names told apart. Tested against a fake ALSA library, no real controller was available.
- Auto-update on Linux: the updater downloads `NyrexVJ-linux-x64` from the nightly build or the latest release, checks its SHA-256 from `SHA256SUMS.txt` and that it really is a Linux program, and replaces the running file atomically. It needs libcurl, and when libcurl is missing the update card says so. Tested against a local web server (download progress, redirect, error codes, refused connection, missing library).
- FFmpeg on Linux: the video libraries are also found in `NYREXVJ_FFMPEG_DIR`, in an `ffmpeg` folder next to the program and in the user data folder, not only on the system library path, so a portable folder with the program and an FFmpeg 8.x build works.
- Build and release: one workflow now builds and tests Windows and Linux (shader check, a short start of the program on a virtual display, dependency check) for every push and pull request, and a separate step publishes. A tagged release is only published when both builds pass. If only the Linux build fails, the nightly still gets the Windows files so Windows updates never wait for Linux.
- New files `docs/DEPENDENCIES.md` (what a release needs, every optional library with its file names and override variable, build requirements) and `THIRD_PARTY_LICENSES.md` (versions, licenses and full texts of GLFW, Dear ImGui, nlohmann/json, stb and glad).
- Fixed: the build failed with the GCC 11 that Ubuntu 22.04 ships because of one C++20 time function. All sources now compile with GCC 11 and GCC 13.
- Fixed on Linux: with the portable FFmpeg builds the program could abort when it tried VA-API, Intel QSV or VDPAU on a computer without the matching libva or VDPAU libraries. NyrexVJ now checks for these libraries first and reports the missing file in the hardware decoding table instead.

## 0.19.0 - 2026-11-20

- Hidden layers cost almost nothing: a layer whose opacity is at 0 (or 0.1 percent and below, including audio modulation) is no longer drawn, neither its clip nor its effects nor its blend pass. Its preview in the layer strip is still refreshed, at about 7.5 times a second instead of every frame, and a layer with a feedback effect such as Trails is always drawn so its trails do not reset. In the test environment a composition with three of four layers faded out needed 47 instead of 146 ms per frame, one with opacities 1, 0.5, 0.25 and 0 needed 96 instead of 134 ms, and a composition with all layers visible is unchanged. The output is identical to the picture before, pixel by pixel.
- Layer resolution: Settings, Performance, Render quality draws the clips and effects of every layer at 75 percent (Balanced), at 50 percent (Performance) or lets NyrexVJ choose (Automatic, 100 down to 50 percent in small steps, only while a frame takes longer than your frame budget). The master effects, the colour and level stage, the transitions and every output stay at full resolution. In the test environment frame times fell by 38 to 40 percent at 75 and by 66 to 67 percent at 50. Full quality is the default and changes nothing. Effects that work on the pixel grid (Pixelate, Halftone, Scanlines and the like) look coarser at the lower settings.
- Less video memory: a render target that was allocated for transitions and never used is gone, the two transition pictures are freed five seconds after the last transition (15.8 MiB at 1080p) and the reduced layer resolution frees the full-size layer pictures (27.7 instead of 39.6 MiB of render targets at 1080p and 50 percent).
- Pass profiler: Settings, Performance, Where the GPU time goes shows, after you tick Measure every render pass, the GPU time of every clip, every effect, every blend and the final stage with its share, and warns about a pass that takes a quarter or more. It is off at start and not saved. The measurements are new command line options (--profile with --bench-comp, --bench-shaders, --bench-memory, --quality) and a script that writes the benchmark presets, see docs/PERFORMANCE.md.
- What was measured and what was not: everything above comes from a software OpenGL driver without a graphics card, so the saving of skipped work and fewer pixels carries over but the milliseconds do not. Nothing was measured next to VRChat or in VR. Several ideas were tried or weighed and left out (constant tables in the blur and glow shaders gave no gain), see docs/adr/0011-render-pipeline-optimisation.md. Please run NyrexVJ --bench-shaders 30 on your computer and share the file.

## 0.18.0 - 2026-11-20

- Hardware video decoding: H.264, HEVC, AV1 and VP9 can be decoded by the graphics card (Direct3D 11, DXVA2, NVIDIA CUDA and Intel QSV on Windows, NVIDIA CUDA, VA-API, Intel QSV and VDPAU on Linux). Settings, Performance, Decoder offers Automatic (large videos on the graphics card, small ones on the processor), Prefer hardware and Force software. NyrexVJ tests every interface once for H.264, HEVC and AV1 and shows the result. If the graphics card cannot decode a video, or stops while it plays, the processor takes over by itself and the reason is shown. This was written against FFmpeg's interfaces and could not be tried on a real graphics card yet, so please report what happens on yours.
- HAP, HAP Alpha and HAP Q go to the graphics card as compressed textures without being unpacked on the processor. In the test environment the processor time for HAP fell from 26 to 6 percent of one core (1080p) and from 105 to 10 percent (4K), and four HAP videos in 1080p use 8 instead of 32 MB of video memory. Without S3TC support, or for an unusual HAP file, the processor decoder is used and the monitor says why.
- Other videos: the colour conversion and the scaling moved from the processor to the graphics card (8 to 16 bit, with alpha, with the right colour matrix). Four H.264 videos in 1080p need 52 instead of 76 percent of one core. The price is more video memory (14 instead of 8 MB per 1080p video); the setting Colours converted on the graphics card turns it off.
- Frame rate limit: Settings, Performance, Frame rate limit with 30, 60, 90, 120, 144 or Unlimited, independent of VSync and with an exact pause between frames, so the processor rests and the frame times stay even. It is now 60 by default, so NyrexVJ no longer draws 144 frames a second on a fast monitor. Choose Unlimited for the old behaviour.
- Video monitor: Settings, Performance, Videos shows for every playing video the decoder and the hardware interface, the route to the graphics card, the reason for a fallback, decode time, upload time, dropped and late pictures and the video memory, split into pictures, colour planes, HAP textures and upload buffers. The Clip window shows the decoder of its clip. The memory numbers are estimates.
- Fixed: a looping video lost a few pictures at every restart. New command line options measure the cost of videos (--bench-video) and check the graphics card path against the processor path (--video-selftest), see docs/MEDIA.md and docs/adr/0010-video-decode-pipeline.md. Direct hand-over of decoded pictures to OpenGL (zero copy) is not implemented and nothing was measured in VR or next to VRChat.

## 0.17.0 - 2026-11-20

- Unreal Engine plugin (experimental): the folder integrations/unreal/NyrexVJ is a plugin with Blueprint nodes for the music data of NyrexVJ (audio levels, spectrum, BPM, beat number and phase, your named parameters) and the events On Beat, On Onset, On Connected and On Disconnected, and with nodes that send controls back (master level, layer opacity, column, deck, tap or any /nyrex/ address). ## 0.15.0 - 2026-11-19

- Stage control: the new Settings page Stage turns controls into DMX. Every channel (universe 1 to 4, channel 1 to 512, optional 16 bit) follows a fixed value or any modulation source: an audio band, an LFO, a macro, the beat or the bar, so the same sources that move an effect can move a light. Test patterns (all on, ramp, chase) check the setup.

The channel to block order is not yet checked against a real VRSL world or HNode, and nothing was tried with a real Art-Net node or VRChat, see docs/DMX.md.

## 0.14.0 - 2026-11-19

- Several outputs: up to four output windows, each on its own display, with its own Open, Fullscreen and Test pattern. Settings, Output has a tab per output. With the default settings the first output looks exactly as before.
- Projection mapping and warping: every output shows a part of the picture you choose (for example the left half), can be mirrored, and its four corners can be dragged in a live canvas so a tilted projector fits a wall. A warp grid from 2 x 2 to 9 x 9 points bends the picture over curved or uneven surfaces.
- Edge blending and several projectors: soft fades for the edges where projectors overlap, with curve, gamma and brightness, and Arrange outputs sets up a grid of up to four projectors with the right overlap in one click. The test pattern shows the grid, corners and blending on every output.
- NDI output: Settings, Output, NDI sends the main picture to OBS, Resolume, vMix and other programs over the network. NyrexVJ does not ship the NDI library, install the free NDI Tools or Runtime. It only reads the picture back while a receiver is connected. Tested with a stand-in library, not yet with the real NDI runtime, see docs/OUTPUTS.md.

## 0.13.0 - 2026-11-19

- Image clips: put .png, .jpg, .bmp, .tga or .gif files into the new media folder, or drag them onto the NyrexVJ window, and they appear in the Library as clips (filter Media). PNG and TGA keep their transparency, so a logo with soft edges lies over the layers below it. Every layer is now composited with transparency; all older looks render exactly as before.
- Video clips: .mp4, .mov, .m4v, .mkv, .avi and .webm files play as clips, including H.264 and HAP (also with transparency). Videos loop with the tempo, follow Speed and Pause, never stall the picture while they load and are released when unused. Video needs the FFmpeg libraries, which are not part of NyrexVJ: the Clip window of a video clip shows the files you need and the folder to put them in, see docs/MEDIA.md.
- Dragging files onto the window copies images, videos and 3D models into the right folder and adds them to the Library at once.

## 0.12.0 - 2026-11-19

- Macros: eight knobs, Macro 1 to 8, in the Master panel under Macros and LFOs. Pick a macro as the source of any audio reactivity slot, of a layer, of the master or of an effect, and one knob moves everything that uses it. The knobs can be mapped to a MIDI controller or driven over OSC like every other control (macro/1 to macro/8).
- LFOs: four tempo synced oscillators, LFO 1 to 4, with the shapes Sine, Triangle, Saw, Square, Random and Smooth random, a cycle length from a quarter beat to 32 beats and a start phase. They follow the tempo and Tap, Resync and Pause, so a sweep always stays on the beat, and they are available as a source everywhere a band can be picked. They are saved with the preset and covered by undo.
- Beat grid: the new sources Beat and Bar rise from 0 to 1 over one beat and over one bar. Click the beat display in the transport to set the beats per bar (2 to 8), to nudge the grid by a sixteenth of a beat, to snap it to the nearest beat or to make the nearest beat the start of the bar. Presets and sessions of older versions load unchanged.

## 0.11.0 - 2026-11-18

- 10 new blend modes, 14 in total: Subtract, Difference, Exclusion, Overlay, Soft Light, Hard Light, Lighten, Darken, Color Dodge and Linear Burn join Normal, Add, Screen and Multiply. Old presets and sessions load unchanged.
- Undo and redo in the main window: the new Edit menu, Ctrl+Z and Ctrl+Y (or Ctrl+Shift+Z) take back and bring back every change to the layers, clips, effects and the master. Playing columns, tempo and the active deck are never rolled back, so undo cannot disturb a running show. The Clip Creator keeps its own undo.
- Preview without playing: Ctrl+click on a clip (or Preview without playing in its right click menu) shows it in the Preview window while the output keeps playing what it played. The Preview window says whether it shows Live or Preview and has a Play now button that sends the shown clip on air.
- Performance: the status bar shows CPU and GPU time per frame, Settings, Performance has a frame time graph with percentiles, a budget in frames per second that turns the numbers red when you miss it and a cost estimate of the loaded composition. NyrexVJ --bench-comp FRAMES measures the loaded composition, --bench-all every factory look, and --bench-budget MS makes the exit code 2 when the average frame is too slow, so a slow look is found before the show.
- Clip Creator cameras: a scene can hold up to eight named cameras. Pick the one that plays or let the clip cut between all of them every few beats. The old single camera of existing scenes stays the first camera and older versions of NyrexVJ still play it.
- Crash protection: the session is saved every 30 seconds and the last ten autosaves are kept in the recovery folder together with the unsaved Clip Creator scene. After a crash or a power cut the next start asks which autosave to continue from instead of loading the old state blindly, offers the unsaved Creator scene and shows the crash report and the end of the log for bug reports. Session files are now written in a way that cannot leave half a file behind.

## 0.10.0 - 2026-11-18

- Spout input: four new clips, Spout Input 1 to 4, show the picture of another program that sends through Spout, for example Unreal Engine, TouchDesigner or a game (Windows). Pick the sender in the Clip window or leave it on Automatic. The image is fitted into the layer, takes effects like every other clip, connects again by itself when the sender returns and shows a placeholder while there is none.
- OSC output: Settings, Control, OSC output sends tempo, beats, bass, mid, high, level, kick and 32 spectrum bands to any program that listens for OSC, 60 times per second by default (off by default, only this computer unless you enter another address). The messages are documented and versioned, schema 1.
- Your own values over OSC: add up to 16 named parameters, each following one control of NyrexVJ such as a layer opacity or the master level, and receive them as /nyrex/out/param/name with a value from 0 to 1.
- Unreal Engine: the new guide docs/UNREAL.md explains how to bring Unreal pictures in through a community Spout plugin and how to read the OSC data with Unreal's built-in OSC plugin. There is no NyrexVJ plugin for Unreal and the Spout input was not yet tried with a real Unreal sender, see the guide.

## 0.5.0 - 2026-11-18

- Live control over OSC: switch it on under Settings, Control (off by default, port 9010, only this computer unless you allow others). NyrexVJ then answers to 207 addresses under /nyrex/ for the master, the 16 decks, the 8 columns, every clip, layer opacity, speed, scale and colour, bypass, solo, clear and all effect switches and parameters. Send a value from 0 to 1, or nothing at all to fire a trigger. It works with TouchDesigner, Max, Pure Data, Python scripts and anything else that speaks OSC.
- MIDI controller mapping on Windows: pick your controller, press Add mapping, choose what to control and move a knob or press a key to link them. Faders and knobs set values, keys trigger clips, columns and decks or switch things on and off, and Invert flips a fader. Mappings are saved in controls.json.
- New Control page in the Settings window with the status of OSC and MIDI, the last message that arrived, the mapping list with Learn and Remove, and a searchable list of every OSC address that copies it with one click.
- Updates are sturdier on Windows: if Windows refuses to swap the running program (error 5), NyrexVJ now retries, picks a free backup name and, if that still fails, finishes the update right after you close it. A failed update shows a button that opens the download page.
