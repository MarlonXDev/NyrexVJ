# ADR 0062: Audio reactive 3D materials: more sources and material targets for the bindings of a scene

- **Status:** Accepted for the new sources, the six material targets, the four rows, the switch and the notes for unknown keys, requested by MarlonXDev (2026-11-27 20:32, prompt 39): let the music move the material of a 3D scene, with clips and presets that keep it and a preview that repeats exactly. One question is open (below).
- **Date:** 2026-11-28
- **Owners:** Maintainers (pending assignment)
- **Related:** [SCENE3D.md](../SCENE3D.md), [INTERFACES.md](../INTERFACES.md), [PERFORMANCE.md](../PERFORMANCE.md), [TESTING.md](../TESTING.md), [ADR 0004](0004-scene-document-and-clip-pack.md) (the scene document and the clip pack), [ADR 0005](0005-pbr-shading.md) (the material model), [ADR 0006](0006-clip-creator.md) (the editor), [ADR 0025](0025-3d-engine-2.md) (morph targets and skinning), [ADR 0058](0058-audio-analysis-beat-tracker-latency-bands-and-channels.md) (the analysis that feeds the sources, unchanged)

## Context
- State at main `ea9ebd0` (0.67.0): every node of a scene can carry audio bindings. A binding is a source (Bass, Mid, High, Level, Kick), a target and an amount. The targets are Size, Glow, Twist and Lift on an object, Light intensity on a light and Zoom on the camera. Each object, light and camera had two rows. `evaluateSceneFull` adds up the bindings of a node once per frame on the processor and the result goes into the model matrix and one glow value per instance. A child node inherits what its parent got.
- The material itself was never touched by the music. The PBR shader got the base colour, metallic, roughness and glow from the scene and one `uKick` for the exposure. The 128 bins of the spectrum, the beat clock and the three band levels already exist in `AudioFeatures` and in `Engine::beat_`. The Clip Creator previews a scene with `virtualAudio(beat, time)`, a fixed function of the two numbers, so a preview can repeat.
- The scene document is JSON inside a `.nyxclip` pack. It has `"version": 1`; a higher number is refused with a message that names it. A binding with a key the program does not know was read as the default source or target without a word, so a typo or a key from a later program became a silent Bass to Size.
- Not part of this change, by the wording of the request: more audio analysis (prompt 31), the 3D renderer itself (prompt 04) and procedural geometry (prompt 32).

## Decision
1. **Two kinds of new sources.** `Beat` is a pulse from the beat position, `exp(-5 * fract(beat))`, the same curve the virtual preview uses for the kick, so it moves with the beat clock (tap tempo, MIDI clock, Link) when there is no usable signal. `Band 1` to `Band 8` are the mean of 16 neighbouring bins of the 128 logarithmic bins (about 30, 66, 144, 316, 690, 1,500, 3,300, 7,300 and 16,000 Hz between the edges). Both are computed by two small functions in `scene_model.cpp` from numbers the engine already has: `beatPulse(beat)` and `spectrumBands(spectrum, bins)`. A bin that is not a number counts as 0 and every bin is held between 0 and 1. Nothing is analysed again.
2. **Six new targets on objects.** Every one is a sum over the bindings of a node (several rows on the same target add up) and a child inherits the sum of its parent like it does with Glow:
   - **Colour shift** turns the hue of the base colour and of the glow colour around the grey axis by `amount * source` turns (clamped to 8 turns). A whole turn comes back to the start colour; 1/3 turns red into green.
   - **Roughness** adds to the roughness before it is clamped to the range the shader already uses (0.045 to 1), so a negative amount makes a shiny surface shinier. The sum is clamped to plus and minus 1.
   - **Texture shift X** and **Y** add to the texture coordinates of every texture lookup of the material (colour, metallic-roughness, normal and glow map), clamped to plus and minus 8. The textures repeat, so a shift by a whole number comes back to the start.
   - **Inflate** moves each vertex along its normal by `0.25 * amount * source` times the half diagonal of the mesh bounding box (clamped to plus and minus 1).
   - **Ripple** adds a travelling wave on the same normal, `0.12 * amount * source * radius * sin(dot(p / radius, (3.1, 4.3, 2.7)) + 5 * time)`.
   The deformation runs in the vertex shader after the morph targets and before the skin, in the local space of the mesh, so scale and animation of the node apply on top. It adds two uniforms to each draw and no vertex data.
3. **Four rows.** `kDocMaxBindings` is 4 (it was 2). The editor shows four rows with 14 sources and 10 object targets; lights keep Light intensity and the camera keeps Zoom.
4. **Old files stay old.** A scene document is written with `"version": 1`, byte for byte as before, as long as it uses only the five old sources, the six old targets and at most two enabled rows. When it uses anything else it is written as `"version": 2`. A 0.67.0 program refuses a version 2 scene with its existing message ("made with a newer NyrexVJ") instead of playing it wrongly. This is `docRequiredVersion`; the writer asks it, nothing is stored.
5. **Unknown values are dropped and said so.** A binding whose source or target is not a known key, a binding that is not an object and a binding after the fourth are not used. The scene still loads and plays. Each one adds a line to the notes of the document (at most 16, then one line "more notes were left out"; a key is shown without control characters and cut to 24 characters), and the notes appear with the other warnings in the Clip Creator and in the log. A light or camera binding with a target that does not fit is changed to the one that does, as it always was, and now with a note. This replaces the silent default.
6. **The switch.** `Settings::sceneMaterialBindings`, key `sceneMaterialBindings`, default true, written to `settings.json` only when false (Settings, Performance, "Music moves 3D materials"). When it is off the six material targets are not evaluated and the material is drawn as authored; Size, Glow, Twist, Lift, Light and Zoom do not change. The Creator preview follows the same switch.
7. **Same numbers in preview and show.** `SceneFrame::setAudio(features, beat)` fills the bass, mid, high, level and kick values, the beat pulse and the eight bands from one `AudioFeatures`. The engine, the thumbnails and the Clip Creator all call it. With "Simulate audio" the preview feeds it `virtualAudio(beat, time)`, which is a pure function, so the same moment gives the same picture. Presets keep the clip by name and the clip pack keeps the bindings; there is no new state.
8. **Robust against bad numbers.** `audioValue` returns 0 for a value that is not a number, and each material sum is clamped (a value that is not finite becomes 0), so a broken analysis cannot put a NaN into a matrix or a uniform. The amounts of a document were clamped to plus and minus 20 before and still are.
9. **Cost.** Per instance the evaluation adds up to four multiplications for the rows; an instance has six more numbers (24 bytes). The shader gets a branch on `uInflate`, `uRipple` and `uHue` that is not taken for a scene without material bindings. No texture, no buffer, no thread and no readback is added, so the graphics memory does not change.

## Measured
All values come from `nvj_matbind_tests` and `NyrexVJ --scene-selftest tests/data/models` on Linux with Mesa llvmpipe (software OpenGL on the processor, one machine, not a graphics card).
- Unit tests: `nvj_matbind_tests` is new, 867 checks, 0 failed (the beat pulse and its wrap and bad values, the band means for flat, low, high, broken and too short spectra, every source reaching a target, every material target and its clamps, the switch, inheritance, repeating exactly, the document keys and their round trip, version 1 for old scenes and version 2 for new ones, unknown keys and their notes, the fix for a light and a camera, the notes reaching the build warnings, a clip pack round trip and the setting).
- Render tests: the scene self test has 22 new checks and passes 46 of 46. A red sphere turns green with a third of a colour turn (the mean colour of the lit pixels goes from about 187, 44, 52 to 39, 197, 56) and a whole turn leaves the picture byte for byte; roughness changes the shine of a metal sphere; a texture shift moves the texture and a whole shift comes back with 0 different pixels; Inflate makes the sphere cover 51 % more pixels and a negative amount 40 % fewer; Ripple changes the surface, moves with the time and repeats exactly at the same time; with the switch off the picture of a bound scene equals the picture of an unbound one (0 different pixels) while Size still follows the music; two players with the same bindings give the same bytes in 12 different music moments; a document with an unknown source and an unknown target plays and has two notes.
- Mutation probes (a fault put into the shader, then reverted): hue ignored, 1 check failed; texture shift ignored, 2 failed; Inflate and Ripple ignored, 4 failed; the switch ignored, 2 failed.
- Evaluation on the processor, 512 instances (64 objects with a ring of 8), best of three rounds, three runs: 70.7 to 77.7 microseconds without bindings and 83.5 to 87.1 with four material bindings on every object, that is 13 to 16 microseconds more per frame.
- Frame time of 24 spheres at 256 x 256 on llvmpipe, 40 frames, three runs, average: 6.0 to 6.3 ms without bindings, 5.2 to 6.2 ms with the bindings and the switch off, 5.6 to 7.9 ms with them on. The difference is inside the noise of this machine; a number for a graphics card does not exist yet.
- Graphics memory: no change (no new texture or buffer).

## Not done
- **Recomputing the normals of a deformed mesh.** Inflate and Ripple move the vertices and keep the old normals. A small push looks right; a deep ripple on a sharp shape lights the surface as if it were still flat. A correct normal needs the neighbours of every vertex or a second pass, and the request did not ask for it.
- **Colour, roughness and texture shift in the classic shading.** The built-in scenes use it and have no material bindings. Inflate and Ripple live in the vertex stage that both use, the other three are in the PBR fragment shader only.
- **Metallic, opacity, an RGB tint, the strength of the glow texture** as targets. Colour shift, Roughness and Glow cover what was named; the others can be added the same way when someone needs them.
- **Per-band split of the analysis for the eight bands.** The eight bands are fixed slices of the existing spectrum. The three band levels (Bass, Mid, High) keep following the band split of Settings, Audio.
- **A real graphics card, Windows at run time (built in CI only), a long show and the combo lists of the editor operated by hand.** See `M-MBD-1`.

## Open question for the maintainer
- Texture shift follows the source: when the level falls, the texture slides back. A scroll that keeps going (the speed follows the music and the offset adds up over time) is a different feature. It needs a value that is kept between frames, so the preview would no longer repeat from one moment alone. Should it be built, and should it be a separate target ("Texture scroll")? Nothing was built on a guess.

## Consequences
- `Settings` has one new field and `settings.json` one optional key; older programs ignore it.
- A scene that uses no new source, no new target and at most two rows is written exactly as before and opens in older programs. A scene that does is written as version 2 and is refused by 0.67.0 and older with the existing message.
- A binding with a key the program does not know is no longer a silent Bass to Size: it is dropped and named. A clip pack from a later version with a new key therefore plays without that binding and says so.
- The shader program of the scene renderer has six more uniforms. Not run on a real graphics card or on Windows beyond the CI build; see `M-MBD-1`.
