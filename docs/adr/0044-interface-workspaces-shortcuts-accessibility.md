# ADR 0044: Workspaces, editable shortcuts, interface scaling, high contrast, keyboard navigation, node canvas zoom and recovery from damaged interface files

- **Status:** Accepted for the automated part (requested by MarlonXDev as prompt 26). Issue [#116](https://github.com/MarlonXDev/NyrexVJ/issues/116). No check has run on a real 125 to 200 percent display, a 4K screen, a small laptop screen, with a screen reader (not possible, see below) or on Windows at run time.
- **Date:** 2026-11-25
- **Owners:** Maintainers (pending assignment)
- **Related:** [manual chapter "Interface, workspaces and accessibility"](../manual/manual.en.md), [INTERFACES.md](../INTERFACES.md), [KNOWN_ISSUES.md](../KNOWN_ISSUES.md), [TESTING.md](../TESTING.md), [ADR 0043](0043-release-quality-gates.md)

## Context
The interface was usable but fixed in three ways that matter to people who work in a dark room, on a large or a small screen, or without a mouse: one layout file that was rebuilt only when it was missing, keyboard shortcuts that were written into the code, and a size slider that scaled the font and nothing else. A damaged layout or settings file was not recognised. The prompt asked for workspaces, movable panels, shortcuts of the user's own, a visible focus, scalable controls, contrast options and a way back to the default, without rewriting the interface.

## Findings (what existed before)
- **Existed:** Dear ImGui 1.93.0 with docking and seven main panels, a layout file `layout_v6.ini`, ten colour themes, eight languages, a button Settings, Appearance, Reset window layout, a read-only list of shortcuts on the settings page Shortcuts, and an Interface size slider (0.7 to 1.8).
- **Existed, not enough:** the size slider scaled only the font; spacing, rounded corners and scrollbars stayed at pixel values, and many windows opened at a fixed pixel size. The shortcuts fired whether or not extra modifier keys were held (`B` also fired with `Ctrl`). The dim text colour was about 4.4 to 1 against the panel colour, below the 4.5 of the WCAG for normal text (by hand). The focus colour was the accent without a check. A damaged `settings.json` gave defaults and was overwritten on the next save without a copy.
- **Not found:** named workspaces, reading the display scale of the screen, keyboard navigation of controls (`NavEnableKeyboard` was never set), a high contrast look, a check of a layout file before it is loaded, a way to reset the interface when the window cannot be used, an interactive zoom of the node canvas (the Zoom node is an effect and unrelated).
- **Not possible:** support for screen readers. Dear ImGui draws everything itself and has no accessibility tree; its own documentation says that accessibility features are not supported. It is listed as a known issue and not promised.
- **Not verified before this version:** every contrast number, any display scale other than 100 percent, keyboard-only operation.

## Decision
1. **Workspaces are plain layout files.** A workspace is the text that Dear ImGui writes for its windows and docking (`SaveIniSettingsToMemory`), with a header of comment lines (a signature, the format number, the program and the window size) and stored as `workspaces/<name>.ini` in the data folder. Loading applies it with `LoadIniSettingsFromMemory`. Dear ImGui's own format was kept because it carries docking data and needs no converter. `core/workspace` has no OpenGL and no ImGui and is unit tested: it checks a layout before use (size at most 256 KiB, at most 6000 lines and 400 windows, no control characters, only valid sections, dock lines that are dock nodes, coordinates within plus or minus 32000, at least one window), cleans a name (forbidden file name characters become spaces, 40 bytes, reserved Windows names refused, case-insensitive match), keeps at most 32 workspaces, writes through a temporary file and a rename, and lists damaged files as damaged without touching them. A workspace holds the layout only, not clips or settings.
2. **Damaged files are set aside, never deleted.** At the start `layout_v6.ini`, `settings.json` and `shortcuts.json` are inspected. A file that fails is renamed to `<name>.bad`, defaults are used, and a message of about twelve seconds says what happened. A `shortcuts.json` of a newer format version is left alone and the defaults are used for the run; when the user changes a shortcut, the newer file is first renamed to `.bad` so that nothing is overwritten without a copy. `--reset-layout` and `--reset-interface` do the same on request for a window that cannot be used; `--reset-interface` also sets the shortcut file aside and resets interface size, display scale, contrast and keyboard navigation (not the theme or any other setting).
3. **Shortcuts are a table in the core.** `core/shortcuts` holds 13 actions (tap tempo, blackout, fullscreen, undo, redo, settings, record, manual, next and previous deck, larger, smaller and normal interface size), a binding with a key name and three modifiers, parsing and formatting (`Ctrl+Shift+R`), a refusal of a binding that another action uses (the message names that action) and of reserved bindings (the number keys 1 to 8, `Ctrl+Shift+Z`, `Alt+F4`), and a versioned JSON file `shortcuts.json` (`version` 1, all actions written). A file without a version number or not valid JSON is damaged; a newer version is not touched; unknown actions and unknown keys in a file are skipped. **Behaviour change:** the modifiers must match exactly. Before, `B`, `Space`, `F11`, `F1` and the page keys fired with any modifier held. The number keys and the editors' own keys (`Ctrl+Z`, `Delete`, `Space` in the Clip Creator, node editor, timeline and shader editor) stay fixed and are not part of the table.
4. **Interface size scales spacing as well, through a helper and not a rewrite.** The size slider covers 0.7 to 2.5 (was 0.7 to 1.8). The theme function takes a size scale, resets the style and applies `ScaleAllSizes`, so paddings, rounding and scrollbars follow the font. A small set of helpers in `ui_common.hpp` (`ui::px`, `ui::setNextWindowSize`, `ui::setNextWindowSizeConstraints`) multiplies fixed pixel sizes and keeps a window inside the main window (16 pixels of margin); 26 files were changed mechanically for calls that set a window size or a numeric item width. About 80 other literal sizes (`ImVec2(N, M)`) were left as they are. Match the display scale (`uiAutoScale`, off by default) multiplies the result with the content scale of the window's monitor (clamped to 0.75 to 4).
5. **High contrast is a second palette.** `uiContrast` is `standard` or `high`. The high contrast palette is black with white text, stronger borders, a yellow focus ring and the theme accent lightened towards white. The standard dim text colour was raised slightly (0.60 on the scale) to clear 4.5 to 1. `core/contrast` implements the WCAG formula; `nvj_theme_tests` computes about 470 ratios for all ten themes in both looks (normal text 4.5 or 7, large or non-text parts 3) and fails the build when one drops below its limit.
6. **Keyboard navigation is optional.** `uiKeyboardNav` (off by default) sets `NavEnableKeyboard`. While a control has the focus and the focus ring is visible, `Space` presses the control and does not tap the tempo. The ring keeps its fixed thickness; its colour follows the accent or the high contrast yellow.
7. **Settings keys are written only when they differ from the default.** `uiScale` is always written as before; `uiAutoScale`, `uiContrast` and `uiKeyboardNav` appear only when changed, so the frozen compatibility files of 0.50.0 are still produced unchanged and an older program that reads a newer `settings.json` ignores the new keys. Out-of-range or wrong-typed values read as the defaults (`uiScale` is clamped to 0.7 to 2.5 on load and save).
8. **The node canvas gets an interactive zoom.** `Ctrl` and the wheel zoom towards the mouse (the point under the mouse stays), the wheel alone still pans, the keys `=`, `-` and `0` act while the canvas has the focus, the side panel has Zoom buttons. The range is 0.4 to 2.5 and it is not saved with the effect. The text size follows the Interface size and the canvas zoom together.
9. **The checks run in the real window.** `--interface-uitest` drives the program with key and mouse events and checks the layout panels, workspaces (save, move a panel, load, damaged file, reset), shortcuts (the default, a moved key, modifiers that must match, capture, conflicts, reserved keys, a newer file), interface size and display scale, a table of window sizes from 1024x600 to 2560x1440 at several scales (panels inside the window, settings and manual windows inside it), a workspace saved on a larger window loaded into a smaller one, high contrast, keyboard navigation and the node canvas zoom; it can save screenshots (`NYREXVJ_UITEST_SHOTS`). `scripts/test_interface_recovery.py` starts the real program 15 times with damaged, empty, binary, newer and out-of-range files and the two reset options. Both run in the Linux build job.

## Alternatives considered
- **Workspaces as JSON with our own layout model.** Rejected: it would duplicate the docking state and need a converter that can disagree with the library.
- **Scaling every pixel literal by hand.** Rejected for this version: about 80 places would change for little gain. The helpers cover the windows and widths that matter and the style scaling covers the rest; the rest is listed as a known issue.
- **Making the modifier rule lenient to keep the old behaviour.** Rejected: a shortcut that you move to `Ctrl+K` must not also fire for `Ctrl+Shift+K`, and `B` firing with `Ctrl` held was an accident.
- **Turning keyboard navigation and display scaling on by default.** Rejected: both change how the program behaves for everyone, and no real high-DPI screen was available to try them.
- **A screen reader bridge.** Not possible with this library; a different toolkit would be a rewrite and is not proposed.
- **Storing the node canvas zoom in the effect file.** Rejected: it would change a shared file format for a view setting.

## Consequences
- A person can switch the whole arrangement in one click, move to a larger or high contrast look, use the keyboard, remap thirteen actions and start again from defaults, and a broken file no longer blocks the start.
- Users who relied on `B`, `Space` or `F11` firing with `Ctrl` held will see that it no longer does. The manual says so.
- The standard theme's dim text is slightly lighter than before.
- Spacing now follows the Interface size, so a setting of 1.5 or more changes how dense the main window looks; at 1600x900 and 150 percent it is cramped but usable.
- `uiScale` has a larger maximum (2.5). A file with a larger value is clamped.
- New files in the data folder: `shortcuts.json`, the folder `workspaces`, and `.bad` copies when something was damaged.

## Validation / open questions
- **Run (Linux, Mesa llvmpipe, Xvfb, no graphics card):** `nvj_interface_tests` 427 checks, `nvj_theme_tests` 473 checks, `--interface-uitest` 89 checks (at 1280x720 and at 2800x1600 virtual screens), `scripts/test_interface_recovery.py` 24 checks, `scripts/check_i18n.py` (2660 keys in all seven tables), the whole `ctest` suite (52 of 52), and a look at the screenshots of the self test at several sizes and scales.
- **Not done:** a real 125, 150 or 200 percent display (the display scale was tested with injected values 1.25, 1.5 and 2.0, not with the value of a real monitor), a 4K screen, a small laptop screen, touch input, keyboard-only operation of a whole show, high contrast on a projector or in a dark room, a colour vision check, the Windows build at run time, a workspace moved between two monitors, floating windows after a monitor is unplugged, and a review by someone else.
- **Open for the maintainer:** whether keyboard navigation or display scaling should be on by default; whether the editors' own keys should become part of the table; whether the remaining fixed pixel sizes should be converted; whether a screen reader is a goal that needs a different toolkit.
