# ADR 0039: A shader editor with a live preview inside the program, on top of the existing shader system

- **Status:** Accepted for the local part (requested by MarlonXDev as prompt 24). Issue [#106](https://github.com/MarlonXDev/NyrexVJ/issues/106). Autocompletion, a shader debugger, recovery files, a search and replace, several open files and a preview of image filters are **not built**.
- **Date:** 2026-11-25
- **Owners:** Maintainers (pending assignment)
- **Related:** [SHADERS.md](../SHADERS.md), [INTERFACES.md](../INTERFACES.md), [PERFORMANCE.md](../PERFORMANCE.md), [ADR 0022](0022-shader-2-alpha-multipass.md), [ADR 0030](0030-isf-shader-controls.md), [ADR 0038](0038-gpu-diagnostics.md)

## Context
Shaders were files in the shaders folder that the user wrote in another editor. The program scanned the folder once a second, reloaded a changed file and showed the compiler message in the Clip window, but a file that stopped compiling left its clip dark, so a mistake while editing a clip that was live meant a black layer. There was no editor, no preview apart from the thumbnail and the live layer, and no way to try a change without putting the clip on a layer. The task asked for an integrated live playground that builds on the existing shader clips, hot reload, compile path, error display and node editor, with syntax highlighting, errors with line numbers, a compile that is safe against typing (a debounce) and never blocks the render thread, the last working version kept, a live preview, undo and redo, saving as a shader asset, validated paths and file sizes, limited resources, and tests for an invalid shader, a file conflict, a reload, a graphics driver error and performance. It said not to build a second shader runtime.

## Findings (what existed before)
- **Existed:** the shader files (`.glsl`, `.frag`, `.fs`, at most 128 files and 256 KiB each), `prepareShaderSource` (styles, `#pragma nyrexvj` directives, errors in the form `Line N: message`), the plan of passes with buffers, alpha, channels and controls from Shader 2.0 (v0.29.0) and ISF (v0.37.0), the folder scan every second and `reloadShaderClips`, `Engine::buildPlanPasses` and `runShaderPasses` (also used for the thumbnails), the compiler message in the Clip window with the line number of the user's file (`#line`), the 512 MiB budget for buffers, the atomic file writer and the render pass profiler.
- **Existed, not enough:** a compile error left the clip dark, a compile happened synchronously on the render thread when the clip was first drawn (the stall of a big shader was the driver's compile time), no editor, no way to see a change before it reached a layer.
- **Not found:** any text editor widget in Dear ImGui that does what is needed (a single line `InputText` is limited to a fixed buffer and has no line numbers, highlighting or error lines; the multiline one has neither a highlighter nor a way to mark lines).
- **Not verified:** the behaviour of real NVIDIA, AMD and Intel drivers (parallel compile, rejected shaders, time a compile takes), because there is no graphics card here.

## Decision
1. **No second runtime.** The playground uses `prepareShaderSource`, `planPassFragmentSource`, `clipFragmentSource`, `passProgramFor` (the uniform lookup, taken out of `buildPlanPasses` so both use the same code), `allocateShaderState` and `runShaderPasses` of the existing engine. A shader that works in the playground is compiled by the same code that compiles the saved file.
2. **A pure core and a thin engine part.** `core/shader_editor.*` (in `nvj_core`, no OpenGL) holds the text model with undo and redo, the highlighter, the parser of compiler logs, the compile scheduler, the cost governor of the preview, the file name check, the file stamps, the safe save and the four templates. It is tested by `nvj_shaderedit_tests` (26,163 checks, with random edits and random logs). `Engine` only holds what needs OpenGL (`render/shader_playground.cpp`).
3. **The preview is isolated.** It has its own programs, its own pass state and buffers and its own 480 x 270 target. It never writes into a layer, the output or a clip's buffers, and it never replaces a clip's program. A broken preview cannot darken a live clip, and a live clip is not touched when the preview is released. It is drawn after the end of the main frame's GPU timer, so it never counts in the frame time shown on the Performance page.
4. **The last working version is kept.** A compile that fails (a mistake of `prepareShaderSource`, a compile or link error of the driver, a refused memory budget, a timeout, a text over the limit) changes nothing but the error text and the failure counter; the previous program keeps drawing. Only a successful compile swaps the program and restarts the buffers and the cost governor.
5. **Typing never compiles.** The editor's scheduler waits until 0.6 s after the last key (at most 2.5 s while typing goes on, at least 0.35 s between compiles) and runs one compile at a time; "Compile now" and F5 skip the wait. When a driver offers `GL_ARB_parallel_shader_compile` or `GL_KHR_parallel_shader_compile` (both are in the generated loader), the shaders are compiled and linked by the driver in its own threads and the engine polls `GL_COMPLETION_STATUS` once per frame without waiting, with a 20 s limit; without it the driver compiles during the call (on the spot) and the window says so. The texts of the shaders are prepared on the CPU first, so a mistake of the parser needs no OpenGL call at all.
6. **A cost governor for the preview.** The preview's own `GL_TIME_ELAPSED` query pair is read without waiting. A new working version is drawn one frame at a time until three results are in (so a heavy shader costs at most one frame before the first number), an average over 20 ms draws only every n-th frame (up to every 15th), an average over 120 ms or a single frame over 360 ms stops the preview until the user presses Resume or sends a new working version. A result that was measured for the previous version is dropped.
7. **A custom editor widget.** A line numbered text area with highlighting by `shaderedit::highlightAll` (keywords, types, built-ins, the `uTime`-style uniforms and `#pragma nyrexvj` directives, numbers, comments, preprocessor), error and warning lines (tinted, a mark in the gutter with a tooltip and a clickable list), a caret, a selection (keyboard, mouse, double click selects a word, triple click a line), clipboard, tab indent and Shift+Tab, `Ctrl+/` to comment, `Ctrl+Z`, `Ctrl+Y`, `Ctrl+S`, `F5`, scrolling to the caret, and a context menu. The text is UTF-8, lines over 1,500 characters are drawn cut off (the text is kept), and the text is limited to 256 KiB with an undo history of at most 400 steps and 4 MiB.
8. **Compiler messages are turned into lines.** `parseCompileLog` reads the formats of Mesa (`0:12(5): error:`), NVIDIA (`0(12) : error C1008:`), AMD and ANGLE (`ERROR: 0:12:`), the pass headers of the engine (`Buffer B:`), `Line N: message` and plain lines. At most 200 messages of 400 bytes are kept. A message that no format fits stays in the list with line 0 and is never lost.
9. **Saving writes a shader asset safely.** Names are checked (`validateShaderFileName`: ASCII letters, digits, space, `- _ . ( )`, at most 64 characters, `.glsl`, `.frag` or `.fs`, default `.glsl`, no Windows device names, no path), the folder is the shaders folder, the text is limited to 256 KiB, the file is written atomically (`writeFileAtomic`), a symbolic link or a folder with that name is refused, and an existing file is replaced only after the user said so. Opening a file also checks the size. A file that changed on disk since it was loaded (content, not time) is not overwritten without a decision (Overwrite, Load the disk version, Save as a copy, Cancel); the editor looks at the file once a second and loads a changed file by itself when nothing is unsaved.
10. **Saving is the existing hot reload.** The editor does not push a shader into a clip. Saving a file is what the folder scan already reacts to; the clip reloads by the existing path. What the preview shows and what the saved clip does come from the same code.
11. **Image filters are not previewed.** A `#pragma nyrexvj filter` file needs a layer's picture as its input; the preview says so and keeps the last picture. Media channels of a shader read nothing in the preview (they are transparent, like in a thumbnail), and the controls are at their defaults.
12. **Four templates** (NyrexVJ style, Shadertoy style, a transparent shader with `#pragma nyrexvj alpha`, a two pass shader with a buffer) are compiled and drawn in the real engine by the self test, so they cannot rot unnoticed.
13. **The playground is only there while the window is open.** The engine holds nothing for it when the window is closed or the live preview is off: programs, buffers, target and queries are released on the next frame. The buffers count in the shader memory and in the 512 MiB budget.
14. **Two tests with the real program.** `--shader-editor-selftest` (the engine part: 67 checks) runs the real engine and the real shader folder. `--shader-editor-uitest` (25 checks) feeds key, character and mouse events into Dear ImGui and reads what the editor holds; it covers typing, undo and redo, comments, a selection, saving, a change by another program and the conflict dialog, but not Tab, the clipboard, double and triple click or the name rules of Save As (the unit tests cover the model behind them). Both run in CI.

## Alternatives considered
- **`ImGui::InputTextMultiline`.** Has no line numbers, no highlighting and no marks, and its line handling cannot be extended without copying it. Rejected.
- **A third party editor widget (ImGuiColorTextEdit and similar).** Adds a dependency with a licence to check and a text model we cannot test headless. Rejected for the dependency and the testability.
- **Compiling in a second OpenGL context on a thread.** Needs a shared context (not available on every platform the program runs on and a source of driver bugs). The parallel compile extension gets the same benefit without a second context. Without the extension the compile is synchronous and the window says so.
- **Replacing the clip's program while editing.** Would make the live clip follow every keystroke and darken it with every mistake. The preview is separate, and Save is the explicit step.
- **Autosave or recovery files.** Would write files the user did not ask for and need rules for stale files. Not built; unsaved edits are asked about on close.
- **Killing a shader that runs for too long.** OpenGL has no way to cancel a draw that was submitted. The governor reacts to the cost it measured; a shader that never ends can still freeze the driver, as it can in the clip today. Documented in SHADERS.md.

## Consequences
- New files `core/shader_editor.*`, `render/shader_playground.cpp`, `app/ui_shader_editor.cpp`, `app/shader_editor_dialog.hpp`, `app/shader_editor_selftest.*`, `app/shader_editor_uitest.cpp`, `tests/test_shader_editor.cpp`; new start options `--shader-editor [FILE]`, `--shader-editor-selftest [FRAMES]` and `--shader-editor-uitest`; a Creator menu entry and an "Edit in shader editor" button in the Clip window.
- With the window closed the program behaves exactly as before; no setting was added.
- The preview costs GPU time while the window is open (1.7 to 1.8 ms per drawn frame for a two pass shader on the Mesa software renderer, not a number for a graphics card); the governor limits it.
- 69 new translated texts (seven languages, 2,396 keys in total).

## Validation / open questions
- Done here, on Linux with the Mesa software renderer (OpenGL 4.5 core context): `nvj_shaderedit_tests` (26,163 checks), `--shader-editor-selftest` (67 checks, 3 s, three runs), `--shader-editor-uitest` (25 checks, 48 to 50 s), the whole suite, the translation check, screenshots of the window.
- **Not done:** a real graphics card (parallel compile, driver rejections and compile times were only seen from Mesa, whose shader cache makes small shaders compile in under 2 ms), Windows beyond the CI build (the save conflict with cloud sync or antivirus, the IME and the clipboard), a person typing for an hour, an editor open during a VRChat like show, a keyboard layout with dead keys or an input method with composition (only finished characters are read).
- **Open for the maintainer:** whether to add a search, several open files, autocompletion for the built-in uniforms and the `#pragma nyrexvj` lines, a preview of image filters with a test picture, or a node editor view of the same file.
