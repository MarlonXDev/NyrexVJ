# ADR 0061: GPU effect graph optimizer: skip the passes that only copy, with a switch to turn it off

- **Status:** Accepted for the skipped final pass, the skipped colour copy and the skipped transition copies, requested by MarlonXDev (2026-11-27 20:32, prompt 44): make the effect graph cheaper without changing what it draws, with measurements and a way back. Fusing effects into one shader, removing the copies of feedback effects and not drawing covered layers were looked at and not built (see below).
- **Date:** 2026-11-28
- **Owners:** Maintainers (pending assignment)
- **Related:** [PERFORMANCE.md](../PERFORMANCE.md), [INTERFACES.md](../INTERFACES.md), [TESTING.md](../TESTING.md), [ADR 0060](0060-gpu-feedback-lab-budget-pool-freeze-reset-and-feedback-effects.md) (the feedback buffers keep their copies), [ADR 0045](0045-graphics-memory-diagnostics-and-warnings.md) (the memory estimate), [ADR 0059](0059-transition-designer-custom-glsl-and-isf-transitions.md) (the transition pass). Issue [#152](https://github.com/MarlonXDev/NyrexVJ/issues/152).

## Context
- State at main `e0567b3` (0.66.0): `Engine::render` draws each deck into a render target (`renderDeck`), then runs the master chain, then `finalPass`, which applies the colour grade, the level, Blackout and the hold, forces the alpha to 1 and writes the output. With a colour look (LUT) the result went into a scratch picture first and a second pass copied it back through the LUT. During a deck transition each of the two decks was drawn, passed through `finalPass` into its own picture, and the transition pass blended the two.
- When the grade is neutral, the level is 1, Blackout and the hold are off and the master chain is empty, the final pass writes the same bytes it reads. It is a full extra pass over the picture that changes nothing.
- The layers are composited in a ping-pong between two render targets. A layer with a plain blend (Normal, Add and so on) draws over the accumulated picture in place. A layer with one of the blend modes that read the picture under it (`blend >= BlendSubtract`) draws into the other target and the two swap. Which target holds the result of the last layer therefore depends on how many swaps happened.
- The effects are complete shader programs, 100 and more of them, each with its own passes and uniforms. The feedback effects keep a picture of their own output and copy into it once per frame ([ADR 0060](0060-gpu-feedback-lab-budget-pool-freeze-reset-and-feedback-effects.md)).

## Decision
1. **A plan, then a route.** `src/core/graph_plan.hpp` has the decisions as plain functions with no OpenGL, so a unit test can reach every branch: `finalIsNeutral(grade, level, blackout, hold)` (exact equality, a grade that is off by one step is not neutral), `chainIsEmpty(slots, effectCount)`, `resultStaysInFirst(swaps)` (an even number of swaps leaves the result in the first target) and `planDeckRoute(optimizer, neutral, emptyMaster, colour)`. The route is one of `Final` (the old path), `Land` (the last layer is drawn straight into the deck picture), `Direct` (the same, then the colour look reads that picture and writes the output) and `ViaScratch` (the final pass writes into the other composition target and the look reads it).
2. **Land the last layer where it is needed.** `renderDeck` takes an optional landing target. It counts the swaps the layers will make (visible layers with a swapping blend) before it clears anything and starts the accumulation in the target that makes the result end up in the landing target. Then `settleDeck` has nothing to copy and counts a skipped final pass. If the result sits in the wrong target for a reason the count did not foresee, `settleDeck` runs the normal final pass, so the picture is still right.
3. **Only with an empty master chain.** A master effect can write an alpha other than 1, and `finalPass` forces the alpha to 1. Skipping the pass behind an effect would let that alpha through. So the master chain must be empty. The layer composites keep the alpha of the accumulated picture at 255 (it is cleared to opaque black and the blend functions leave the alpha alone), and the targets are RGBA8 of one size, so for the neutral case the skipped pass is the identity.
4. **The colour look.** With the optimizer on, the look no longer renders into a scratch picture and blits back. `Direct` reads the deck picture and writes the output; `ViaScratch` (a master chain or a grade that is not neutral) writes the final pass into the other composition target and the look reads that. The scratch picture is never made and is freed when the switch is turned on. `colorStageBytes()` is the size of the look only (`cubeGpuBytes`), not the look plus a picture of the output size.
5. **Transitions.** When both decks are neutral and the master chain is empty, the outgoing and the incoming deck land in the two deck pictures that the transition pass reads, so the two final passes go. With a colour look the transition pass writes into a composition target and the look reads that. A switch of the optimizer in the middle of a transition draws the right picture in the next frame; the tests do it.
6. **The switch.** `Settings::graphOptimizer`, default true, key `graphOptimizer` in `settings.json`, written only when it is false, so a settings file that never changed it is written byte for byte as before and an older program ignores the key. A wrong type is repaired to the default. The checkbox is **Skip passes that only copy** in Settings, Performance, Render graph, with a line that counts the passes and copies skipped since the program started or since the switch was last changed. `Engine::setGraphOptimizer` resets the counters only when the value changes. No control id, no network sync field and no preset or show format changes.
7. **Nothing else moves.** The routing engine, the recording and the outputs read the same output picture as before; `routing_engine.cpp` still calls `finalPass` for its own routes. The effects, their shaders, the blend functions and the feedback buffers are untouched.

## Measured
All values come from `nvj_graph_tests` and `NyrexVJ --shader-selftest 200` on Linux with Mesa llvmpipe (software OpenGL on the processor, one machine, not a graphics card), 1280 x 720. Each case runs four rounds that alternate between the optimizer off and on, 200 frames in all per side; "pixel differences" compares the output picture of both modes byte for byte after the run.
- Unit tests: `nvj_graph_tests` is new, 224 checks, 0 failed.
- Render tests: 73 new checks in `--shader-selftest`, 263 of 263 in total, all passed. Every one renders the same frame twice, optimizer off and on, with the same time and state, and compares every byte of the output (RGBA): one to four layers, all 14 blend modes, five blend orders (so odd and even swap counts), a hidden layer that still swaps, bypass, solo, an empty composition, six colour grades, levels 0, 0.4 and 0.9, Blackout, the hold, master effects, a layer effect, a reduced layer resolution, three output sizes, the colour look (direct, half strength, graded, dimmed, with a master effect), fade, Radial, Glitch and a custom transition (neutral, graded, with an effect, with a colour look, switched in the middle) and four feedback scenes of 20 frames each compared as two separate runs. The alpha of the output stays 255 in all of them. Nearly every check also asserts how many passes and copies were skipped, so a route that silently falls back to the old path fails.
- A mutation probe: `finalIsNeutral` was changed to ignore the grade; 9 of the graph checks failed. It was reverted.
- Frame time (average, median, 95th and 99th percentile, worst), optimizer off then on:

- The master effect case does the same work in both modes and still differs by +7 % at the 95th and +14 % at the 99th percentile. That is the size of the noise in the tail on this machine, so the 99th percentile and the worst frame of the other cases are not evidence for or against the change; the average and the median are.
- Graphics memory (the estimate that Settings, Performance shows): with a colour look 32,382,246 bytes off against 28,695,846 on, the difference of 3,686,400 bytes being one picture of 1280 x 720 at 4 bytes. All other cases are identical, because the optimizer makes no new pictures.
- Pixel differences: 0 in all five benchmark cases.

## Not done
- **Fusing effects into one shader.** Each effect is a complete program with its own passes, helpers and uniforms, over a hundred of them, and a chain is chosen by the user. Merging two programs changes the order of operations and the rounding between them, so the picture would no longer be exactly what the effects draw one after the other. The saving (one texture write and read per pair) is small next to the cost of the effects themselves, and the risk is large.
- **Removing the copy of a feedback effect** (rotating buffers or a second render target in the same draw). It would save one copy of one layer per feedback effect, depends on the effect and on the order of the chain, and a mistake shows as a flash or a frozen trail that the 8 bit residue tests of 0.66.0 would not catch. The buffers stay as they are.
- **Not drawing a layer that is covered.** A layer under an opaque one can only be dropped when its effects have no feedback, the covering layer has alpha 1 everywhere and its blend is plain. The alpha of a clip is not known on the CPU and a feedback effect needs to keep running, so this is not safe without per-clip metadata.
- **Skipping the final pass behind a master effect.** It needs a flag for each effect that says its output alpha is 1. Nothing has that flag today.
- **The routing engine.** Its routes keep calling `finalPass`; they read the output picture and were not part of the request.
- **Throttling the previews.** Not part of this change.
- A real graphics card, Windows at run time (built in CI only), two PCs on the network sync, and a run of hours with the setting on. See `M-GRF-1`.

## Consequences
- `Settings` has one new field and `settings.json` one optional key; older programs ignore it.
- The output picture is the same as before in every case the tests cover, bit for bit, with the setting on or off. If a case turns up that differs, the switch brings back the old path.
- With a colour look the engine no longer holds a picture of the output size for the scratch pass, so the estimate of the graphics memory is lower by that size. The memory check of `--color-selftest` expects the look alone when the optimizer is on and the look plus the picture when it is off.
- The gain is the cost of one or two full-screen passes. On a software rasteriser that is 6 to 7 ms per pass at 1280 x 720; on a graphics card it will be a small part of a millisecond, so the saving in milliseconds will be much smaller there while the saving in passes and in memory stays. The setting costs nothing when it is off.
- Not run on a real graphics card or on Windows beyond the CI build; see `M-GRF-1`.
